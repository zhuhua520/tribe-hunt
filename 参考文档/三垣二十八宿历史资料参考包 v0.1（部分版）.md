## 一、资料使用原则

### 1. 历史资料与游戏设定分开

本资料只记录传统天文学中的名称、分类和来源信息。

星官是否成为战斗组件、Boss、时装、基地设施或探索内容，由独立的游戏设计资料决定。

游戏设计不得反向修改历史归属。

### 2. 当前采用的参考来源

**来源 A：香港太空馆《中国星区、星官及星名英译表》**

网址：

https://hk.space.museum/sc/web/spm/resources/teachers-corner/constellations-and-myths/glossary-of-chinese-star-regions-asterisms-and-star-names.html

用途：

- 建立三垣和二十八宿的工作目录。
- 记录星官名称。
- 记录来源表列出的关联星名。
- 作为后续名称和目录层级核对的基础。

**来源 B：《步天歌》（传王希明本）**

网址：

https://zh.wikisource.org/zh-hans/步天歌_(王希明)

用途：

- 核对传统星官名称。
- 参考古代歌诀对星群形状和相对位置的描述。
- 记录歌诀中的星数。
- 发现与现代整理目录之间的差异。

注意：歌诀中的星数属于对应文本版本的记载，不应直接视为所有时代统一的现代星表数量。

### 3. 资料状态

- **已录入：** 已从指定工作目录抄录。
- **待核验：** 需要进一步核对历史版本、组成恒星或归属。
- **存在差异：** 不同来源存在名称、分类或数量差异。

本资料中的空值表示尚未核实，不代表历史上不存在相应内容。

## 四、星官记录的数据模板

以下模板供后续扩充使用。它不要求当前就填完所有字段。

```json
{
  "record_id": "E-JIAO-01",
  "source_id": "SRC-HKSM",
  "region_type": "mansion",
  "region_name": "角宿",
  "symbol": "东方青龙",
  "source_name": "角",
  "normalized_name": "角",
  "record_type": "asterism",
  "parent_record_id": null,
  "related_names": [],
  "constituent_stars": [],
  "reported_star_count": null,
  "verification_status": "source_transcribed",
  "source_notes": [],
  "discrepancy_notes": [],
  "game_mapping": null
}
```

### 字段说明

| 字段 | 用途 |
|---|---|
| `record_id` | 唯一标识 |
| `source_id` | 指定来源 |
| `region_type` | 三垣、二十八宿或其他天区 |
| `region_name` | 所属垣或宿 |
| `symbol` | 所属四象，适用于二十八宿 |
| `source_name` | 来源原文名称 |
| `normalized_name` | 便于检索的规范名称 |
| `record_type` | 星官、关联星名或其他条目类型 |
| `parent_record_id` | 有证据支持的父级记录 |
| `related_names` | 已核验的别名或关联名称 |
| `constituent_stars` | 组成恒星；未核验时留空 |
| `reported_star_count` | 指定来源记载的星数 |
| `verification_status` | 核验状态 |
| `source_notes` | 来源章节、页码或原文线索 |
| `discrepancy_notes` | 历史版本差异 |
| `game_mapping` | 游戏设计映射，历史资料阶段保持为空 |

### 核验状态

- `source_transcribed`：已从工作目录录入。
- `name_cross_checked`：名称已与另一来源核对。
- `verified`：指定版本下的归属或恒星映射已核验。
- `conflict`：来源间存在未解决的差异。

“已录入”不等于“历史考证完成”。

## 五、历史资料与游戏组件的分离模板

历史条目稳定后，可以在独立的游戏设计表中建立关联。

```json
{
  "game_content_id": "GAME-CONTENT-EXAMPLE",
  "history_record_id": "E-JIAO-01",
  "gameplay_type": null,
  "component_category": null,
  "fixed_star_rating": null,
  "element_type": null,
  "element_value": null,
  "weapon_compatibility_tags": [],
  "core_effect": null,
  "random_affix_pool": [],
  "boss_id": null,
  "reward_id": null,
  "design_status": "not_designed"
}
```

以上字段是游戏内容模板，不是历史事实。

后续只有在玩法设计确定后，才填写组件星级、元素值、武器适配标签、核心效果和随机词条。

## 六、后续补充顺序

### 第一阶段：扩充历史目录

1. 补齐房、心、尾、箕等东方七宿。
2. 依次补齐北方、西方和南方七宿。
3. 补齐紫微垣、太微垣和天市垣。
4. 记录来源表中的关联名称及父子层级。

### 第二阶段：补齐历史核验

1. 对照《步天歌》。
2. 核验历史异名和目录差异。
3. 补充组成恒星与星数。
4. 为已核验记录保存具体来源位置。

### 第三阶段：转入游戏设计

1. 筛选适合战斗构筑的星宿与星官。
2. 筛选适合基地、外观、探索和图鉴的内容。
3. 为战斗组件填写游戏字段。
4. 最后再规划区域、Boss 与奖励。
