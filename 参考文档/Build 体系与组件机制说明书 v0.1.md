# Build 体系与组件机制说明书 v0.1

**用途：** 为战斗系统、组件数据、掉落逻辑和 UI 实现提供统一规则。

## 1. 核心概念

### 星宿组件

每套 Build 的核心组件，负责提供一种独特的战斗机制，并可附带少量相关数值加成。

星宿的固有机制固定，不因星级、强化等级或随机副词条而改变。

### 星官组件

辅助组件，提供相对独立的特殊效果，能够与不同星宿组合。

星官的传统所属关系用于资料管理和游戏内容关联，不限制其只能用于所属星宿。

### 组件定义与组件实例

组件定义描述一种组件的固定内容，包括名称、类别、星级、基础属性、核心效果和词条池。

组件实例代表玩家实际获得的一件组件，包含具体随机词条、词条数值及强化状态。

同一组件定义可以生成多个不同实例。

## 2. 装配规则

每套战斗 Build 必须包含：

| 槽位 | 数量 | 职责 |
|---|---:|---|
| 星宿核心位 | 1 | 提供核心战斗机制 |
| 星官位 | 2 | 提供独立词条及机制补充 |

约束：

1. 不允许缺少星宿核心。
2. 两个星官不能是同名星官。
3. 允许使用不同历史星宿关联的星官。
4. 组件实例可以被多套 Build 共用。
5. 同一组件实例不能因被多个 Build 引用而产生重复属性加成。
6. 拆解被 Build 引用的实例前，必须先解除引用或完成明确确认。

同名星官的不同随机词条版本属于不同实例，但仍然受同一套 Build 内不允许重复同名星官的限制。

## 3. 战斗职责划分

### 武器层

武器决定基础攻击动作、攻击距离、攻击节奏和自身攻击特效。

武器品级及其专属属性独立于星宿武装系统。

### Build 层

Build 提供属性加成和额外战斗机制。

组件效果通过明确的攻击行为或战斗事件触发，例如：

- 蓄力攻击命中。
- 重击命中。
- 多段攻击完成。
- 暴击发生。
- 敌人进入破甲状态。
- 元素积累达到既定条件。

以上是可复用的战斗事件示例，不代表所有事件均已实现。

### 战斗结算层

统一处理命中、伤害、状态变化和组件触发，避免不同组件重复编写同一套结算逻辑。

## 4. 组件数据分层

每个战斗组件包含三层数据。

### A. 固定身份数据

- 名称与类别。
- 固定初始星级。
- 元素类型与基础元素值。
- 固有核心效果。
- 攻击行为适用标签。
- 历史资料引用。
- 游戏内关联关系。

### B. 随机副词条数据

当前设计基准为每个掉落实例生成两条随机副词条。

随机副词条从受限词条池抽取，并生成对应数值。

建议采用：

- 一条来自与组件主题相关的词条池。
- 一条来自允许适配的通用词条池。
- 同一实例不重复抽取同一个词条。
- 每条词条具有明确数值范围和叠加规则。

以上抽取规则属于当前设计基准，实际词条池与数值仍需测试。

### C. 玩家成长数据

记录强化等级等玩家培养信息。

强化主要影响数值，不改变固有核心机制，不增加随机词条数量。

强化上限和具体成长曲线暂未确定。

## 5. 随机词条分类

| 分类 | 示例 | 约束 |
|---|---|---|
| 攻击类 | 攻击伤害、暴击率、暴击伤害 | 需设置合理上限 |
| 机制类 | 蓄力、破甲、失衡、连击收益 | 应与组件主题相关或明确适配 |
| 元素类 | 元素伤害、元素积累效率 | 不与基础元素值混淆 |
| 生存类 | 生命、防御、格挡或闪避收益 | 应具有明确适用场景 |

具体词条必须由设计数据定义，不应由程序随机生成未经设计的效果。

## 6. 随机掉落规则

每次生成组件实例时：

1. 确定组件定义。
2. 读取固定星级和固定核心效果。
3. 读取该组件允许的词条池。
4. 抽取两条符合约束的随机副词条。
5. 为每条词条生成合法数值。
6. 保存为独立组件实例。
7. 更新玩家库存和图鉴状态。

同名组件每次掉落时，星级和核心效果保持不变，副词条及其数值可以不同。

首次击败重要 Boss 时，可保证获得指定核心组件；副词条仍按随机规则生成。

具体掉落概率、保底规则和重复奖励尚未确定。

## 7. 星级规则

- 初始星级范围为一至五星。
- 同名组件星级永久固定。
- 高星组件通过更高难度内容获得。
- 星级影响基础数值档位和成长潜力。
- 星级不决定词条数量。
- 星级不改变核心机制。
- 高星数值优势适中，不能完全压制低星组件。

组件的实际构筑价值还取决于核心机制、随机词条和适用场景。

具体星级数值与分布比例尚未最终确定。

## 8. 组件实例管理

### 保留与复用

组件实例可被多套 Build 引用。切换 Build 不要求重复收集同一组件。

### 拆解

拆解不需要的组件后获得成长资源，暂定使用通用资源“星尘”。

被引用或锁定的组件不得被批量拆解。

### UI 管理

最低需求：

- 分类筛选。
- 星级筛选。
- 词条筛选。
- 同名组件比较。
- 收藏与锁定。
- 批量拆解。
- 显示组件被哪些 Build 引用。

图鉴数据独立保存，不因组件实例被拆解而丢失。

## 9. 暂不实现的机制

第一版暂不要求：

- 随机星级。
- 升星。
- 随机核心效果。
- 随机词条数量。
- 词条重铸。
- 锁定一条词条后重新随机其他词条。
- 定向制作任意指定词条。
- 复杂的多层套装。
- 强制五行相生相克。
- 多核心星宿的装配结构。

## 10. 验收标准

- 组件生成符合固定身份定义。
- 随机词条均来自合法词条池。
- 同一组件实例被多个 Build 引用时不会重复计算。
- 同一 Build 不允许装配两个同名星官。
- 拆解操作不会破坏其他 Build 的引用。
- 图鉴与实际库存独立。
- 武器攻击方式与 Build 效果可以独立扩展。
- 星级变化不会改变核心机制或词条数量。
