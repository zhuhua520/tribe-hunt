# 近战关键帧判定规格 v1.0

## 1. 设计原则

近战攻击使用少量关键帧定义判定区域，并通过相邻关键帧之间的扫掠检测覆盖武器运动轨迹。

目标是在开发成本可控的前提下，使攻击判定与视觉动作尽可能一致。

## 2. 攻击阶段

每个攻击动作划分为三个阶段。

### 前摇

- 用于表现攻击准备。
- 默认不产生伤害判定。
- 根据武器规则决定是否允许闪避取消。

### 生效阶段

- 按照攻击数据启用一个或多个判定区域。
- 每个关键帧可以配置区域的位置、尺寸和形状。
- 相邻关键帧之间进行扫掠检测。
- 命中后立即执行统一命中结算。
- 同一次攻击实例对同一目标默认只结算一次伤害。

### 后摇

- 关闭攻击判定区域。
- 处理恢复动画和输入缓冲。
- 根据武器规则开放闪避取消窗口。

## 3. 关键帧数据

每个攻击动作至少需要配置：

| 字段 | 用途 |
|---|---|
| attack_id | 标识攻击动作及攻击实例所属类型 |
| animation_id | 对应角色攻击动画 |
| startup_end | 前摇结束位置 |
| active_start | 判定生效起点 |
| active_end | 判定生效终点 |
| recovery_end | 动作恢复结束位置 |
| hitbox_keyframes | 关键帧判定区域数据 |
| damage_profile | 基础伤害及相关攻击参数 |
| armor_break_profile | 破甲贡献 |
| reaction_profile | 失衡、击退和受击反馈参数 |
| cancel_windows | 允许取消的动作窗口 |

具体帧数和数值暂不固定。

## 4. 关键帧区域

每个关键帧可以配置：

- 时间或动画帧索引。
- 判定区域形状。
- 相对角色或武器的位置偏移。
- 区域宽度、高度或半径。
- 是否启用。
- 对应攻击参数的引用。

优先使用少量关键帧。只有当攻击轨迹复杂到无法通过简单插值和扫掠检测合理覆盖时，才增加关键帧数量。

## 5. 扫掠检测

当攻击判定区域从位置 A 移动到位置 B 时，检测这段运动经过的空间，而不是只检查 A 和 B 两个瞬时位置。

实现需要满足：

- 快速挥砍不会轻易穿过较薄的目标而漏判。
- 攻击区域移动方向与动画方向一致。
- 角色转向或翻转时，判定区域正确镜像。
- 不因关键帧插值产生明显超出武器视觉范围的命中。
- 同一攻击实例不会因为扫掠检测重复报告而重复伤害同一目标。

扫掠检测不意味着将武器整个运动范围无限扩大。判定应贴合合理的武器轨迹。

## 6. 四种原型武器

### 剑

- 三段普通攻击，每段拥有独立的攻击实例。
- 每段可分别配置关键帧和判定区域。
- 一次挥砍可以命中多个不同目标。
- 连击中的下一段可以再次命中此前受击的目标。
- 蓄力斩使用独立攻击数据。

### 重锤

- 普通重击采用单段攻击数据。
- 蓄力攻击使用独立的攻击数据与破甲参数。
- 可以配置较大但方向明确的判定区域。
- 地面下砸及冲击波属于后续扩展，不要求首轮实现。

### 长弓

长弓的主要攻击判定来自箭矢投射物，而不是角色手持弓的近战区域。

如果未来增加近距离弓身打击，应作为独立近战攻击配置。

### 单发火铳

火铳的主要攻击判定来自子弹投射物。

角色举枪、开火和后坐动画可以共享角色动作系统，但只有实际发射时刻才生成子弹。

## 7. 攻击命中记录

每次攻击实例维护已命中的目标记录。

- 首次命中有效目标后记录目标标识。
- 同一实例后续不再对该目标结算普通重复命中。
- 命中其他目标不受影响。
- 下一段连击或下一次独立攻击拥有新的命中记录。
- 攻击结束或实例销毁后释放记录。

## 8. 调试工具

开发阶段建议提供可视化调试：

- 显示角色身体碰撞区域。
- 显示敌人受击区域。
- 显示当前攻击判定区域。
- 显示关键帧之间的扫掠轨迹。
- 标记已经命中的目标。
- 显示攻击处于前摇、生效还是后摇阶段。
- 允许暂停动画并逐帧检查判定。

## 9. 验收标准

- 判定不会明显脱离武器动作。
- 快速挥砍不会频繁漏判。
- 同一次挥砍不会重复伤害同一目标。
- 同一次挥砍能够正确命中多个不同目标。
- 连击每一段能够独立命中。
- 攻击判定可以在不修改核心程序逻辑的情况下调整。
