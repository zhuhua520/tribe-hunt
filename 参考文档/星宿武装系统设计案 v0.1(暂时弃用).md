# 星宿武装系统设计案 v0.1
## ——基于三垣、二十八宿与星官体系的武器 Build 系统

**文档用途：** 游戏系统设计、内容规划、数据表建模、后续程序实现。

**设计目标：** 玩家通过挑战星宿 Boss 获得星宿印记、星官符文及其他战利品，将这些组件装配到武器上，形成不同的战斗流派。不同组件之间存在层级、归属与组合关系，鼓励玩家通过战斗和探索逐渐完善 Build。

---

# 一、核心设计原则

## 1.1 历史资料与游戏规则分离

本方案采用《步天歌》传本作为主要文化资料来源之一。《步天歌》以三垣、二十八宿为主体，按照天区介绍星官、星数和星群之间的位置关系。具体版本在名称、数量及划分上可能存在差异。

参考资料：

- [《步天歌》传本文字——维基文库](https://zh.wikisource.org/zh-hans/步天歌_(王希明))
- [浙江省社科联：《唱享〈步天歌〉，通晓满天星官》](https://www.zjskw.gov.cn/art/2025/3/24/art_1229516293_63139.html)
- [中国科技馆：三垣四象二十八宿](https://www.cdstm.cn/museum/zphc/hxzg2017x/art/2017/art_0afcbc9dfb144531b4c4394fad97ef15.html)

历史名称用于构建世界观、区域划分和收集目录；技能、数值、Boss 行为与套装效果属于原创设计，不应误认为是传统天文学原有的功能。

## 1.2 三个层次，各自承担不同职责

| 层次 | 游戏用途 | 玩家体验 |
|---|---|---|
| 三垣 | 高阶区域、挑战路线、特殊组合体系 | 选择流派方向，解锁高级挑战 |
| 二十八宿 | 主要 Boss、核心 Build 单元、四象进度 | 击败强敌，获得独特战斗机制 |
| 星官 | 模块化 Build 单元、辅助效果、套装触发 | 将核心机制组合成自己的玩法 |

设计重点：

- 二十八宿负责提供有辨识度的核心战斗机制。
- 星官负责调整、强化或改变核心机制。
- 三垣负责组织高阶内容，并让不同星官组合产生更大的流派差异。

不要求每一个星官都设计成独立 Boss。星官可以通过宿主 Boss 掉落、精英敌人、隐藏挑战、宝箱、任务或制作获得。

# 二、Build 系统结构

## 2.1 两类核心组件

### A. 星宿印记

每个二十八宿拥有一个标志性的星宿印记。

- 来源：首次击败对应星宿 Boss，保证获得。
- 定位：Build 核心。
- 装配容量：占用 2 点星位容量。
- 设计要求：每个印记改变一项关键战斗行为，而不仅仅是增加攻击力。
- 重复获取：转化为星尘、强化材料或升级进度。

例如：

**角宿印记：** 蓄力攻击命中后贯穿一个额外目标，并积累破甲值。

### B. 星官符文

每个星官对应一个可收集、可装配的辅助组件。

- 来源：星宿 Boss、精英敌人、探索、任务和特殊挑战。
- 定位：提供触发条件、附加效果或机制转换。
- 装配容量：占用 1 点星位容量。
- 设计要求：星官符文应当能够改变核心印记的使用方式，或为武器提供新的战斗能力。

例如：

**进贤符：** 蓄力攻击命中精英敌人时，额外积累破甲值。

当角宿印记与进贤符组合后，玩家可以专门围绕蓄力、破甲和精英处决构建流派。

## 2.2 武器装配规则

建议每把武器具有 5 点星位容量。

| 组件 | 容量消耗 | 推荐数量 |
|---|---:|---:|
| 星宿印记 | 2 | 最多 2 个 |
| 星官符文 | 1 | 最多 5 个，受总容量限制 |

允许三种典型配置：

- **双宿流：** 两个星宿印记，加一个星官符文。
- **宿官流：** 一个星宿印记，加三个星官符文。
- **纯星官流：** 五个星官符文。

这样可以同时满足核心流派、混合流派和偏向机制组合的玩法。

实际装备界面可以表现为五个星位，星宿印记占据两个相连的星位，星官符文占据一个星位。

## 2.3 套装与共鸣

建议先实现三种组合规则。

**规则一：本宿共鸣**

装备一个星宿印记，并装备两枚归属于该宿的星官符文，激活特殊效果。

例如：

角宿印记 + 进贤符 + 天田符

触发“苍龙破阵”：蓄力攻击破甲后，下一次普通攻击对目标造成额外冲击。

**规则二：四象共鸣**

按照四象划分组件：

- 东方青龙
- 南方朱雀
- 西方白虎
- 北方玄武

装备同一四象的 2 个组件，获得小型共鸣；装备 4 个组件，获得强化共鸣。

四象效果可以形成不同的战斗倾向，例如青龙偏向连续进攻、朱雀偏向范围与元素效果、白虎偏向暴击与处决、玄武偏向防御与反击。这些是游戏中的流派定义，不是历史天文学的既定属性。

**规则三：三垣共鸣**

三垣内的星官符文可以组成独立的高阶共鸣：

- 紫微垣：防御、精准、反击与战斗控制。
- 太微垣：连招、技能衔接、标记与战术执行。
- 天市垣：资源循环、战利品、状态叠加与灵活构筑。

以上是游戏原创的功能映射。

为了控制系统复杂度，第一版不必加入更多套装层级。先验证三种共鸣是否能产生真正不同的武器玩法。

# 三、三垣内容设计

三垣不必简单变成另外三个普通 Boss。更适合将其设计为三个高阶挑战区域，每个区域由多个星官挑战构成，最终面对垣级守关 Boss。

| 天区 | 传统象征 | 游戏区域主题 | 战斗与奖励方向 |
|---|---|---|---|
| 紫微垣 | 天帝居所、宫廷 | 星宫禁域 | 防御、反击、精准控制 |
| 太微垣 | 朝廷、官署 | 天庭演武场 | 连招、技能衔接、战术组合 |
| 天市垣 | 市场、社会秩序 | 星市遗迹 | 资源循环、特殊掉落、构筑变化 |

### 紫微垣

代表星官：北极、北斗、勾陈、四辅、文昌、华盖、天牢等。

玩法设计：

- 敌人强调守护、格挡和反击。
- 玩家需要识破攻击、寻找破绽。
- 奖励偏向防御转进攻、精准打击和反击机制。

### 太微垣

代表星官：太微左垣、太微右垣、五帝座、三公、九卿、明堂、灵台、郎位等。

玩法设计：

- 敌人通过不同攻击阶段配合，形成战术压力。
- 玩家需要利用标记、连击和技能衔接破局。
- 奖励偏向连招、技能重置和多阶段攻击。

### 天市垣

代表星官：市楼、车肆、帝座、列肆、斗、斛、贯索、七公、天纪等。

玩法设计：

- 场景中设置交易、资源和隐藏挑战机制。
- Boss 可以利用召唤物、区域控制和资源争夺制造压力。
- 奖励偏向资源获取、状态叠加、消耗品强化和特殊组合。

垣级挑战可以在玩家获得若干宿印后开放，作为中后期构筑扩展内容。

# 五、星官符文的数据规划

每个星官符文建议只承担一个明确功能。不要让所有符文都提供伤害、暴击、攻速等泛用数值，否则玩家会只选择面板数值最高的组件。

建议使用以下分类：

| 类型 | 主要功能 | 示例 |
|---|---|---|
| 触发型 | 满足条件时发动效果 | 完美格挡后反击 |
| 强化型 | 增强现有机制 | 蓄力破甲增加 |
| 转换型 | 改变攻击行为 | 普通攻击变为穿透攻击 |
| 联动型 | 与其他组件产生配合 | 标记目标后暴击引爆 |
| 资源型 | 改变能量或技能循环 | 击杀恢复星脉 |
| 防御型 | 防御转化为进攻收益 | 格挡积累反击伤害 |

每个星官符文的数据至少包含：

- 唯一 ID
- 中文名称
- 所属天区
- 所属星宿或三垣
- 组件类型
- 装配容量
- 触发条件
- 效果参数
- 套装标签
- 掉落来源
- 稀有度
- 强化等级
- 说明文本

# 六、掉落与奖励设计

星宿 Boss 应当是玩家获得核心 Build 组件的主要途径，但不能把构筑进度完全交给随机掉落。

| 奖励 | 首次击败 | 重复击败 | 作用 |
|---|---|---|---|
| 对应星宿印记 | 保证获得 | 可转化为材料 | 解锁核心机制 |
| 星官符文 | 固定奖励或选择奖励 | 从对应掉落池获得 | 扩展 Build |
| 星尘 | 少量 | 稳定获得 | 强化与制作 |
| 星核材料 | 阶段性奖励 | 持续获得 | 武器成长 |
| 外观、图鉴、剧情 | 章节或挑战奖励 | 条件奖励 | 收集与探索 |

建议遵守三条规则：

1. **首次击败保证有用奖励。** 玩家不应击败强敌后只获得金币或普通材料。
2. **重复挑战提供确定性进度。** 重复获得的核心印记可以转化为材料，不应成为纯粹的废品。
3. **高稀有度组件优先通过挑战条件解锁。** 随机掉落可以加快进度，但不应成为获取关键机制的唯一途径。

星官不必一一对应独立 Boss。可以将一场 Boss 战设计成多个奖励来源：核心宿印为固定奖励，星官符文从相关星官池中选择，隐藏条件则提供特殊版本或外观。

# 七、示例 Build

## 7.1 苍龙破阵流

组件：

- 角宿印记
- 进贤符
- 天田符

效果：

- 蓄力攻击贯穿并积累破甲。
- 对精英敌人的蓄力攻击额外积累破甲。
- 完成本宿共鸣后，破甲目标受到下一次重击时触发额外冲击。

玩法：围绕蓄力、破甲和重击设计，适合攻击节奏较慢、单次命中收益较高的武器。

## 7.2 白虎群猎流

组件：

- 昴宿印记
- 卷舌符
- 砺石符

效果：

- 快速攻击积累星弹。
- 星弹可以追踪已标记目标。
- 对弱点命中可以提高星弹积累效率。

玩法：强调连续命中、弱点识别与远程压制，适合弓、投射武器或具有快速连续攻击能力的武器。

## 7.3 玄武壁垒流

组件：

- 室宿印记
- 羽林军符
- 北落师门符

效果：

- 防御成功后形成短暂护壁。
- 护壁吸收伤害后积累反击资源。
- 完美格挡可以消耗资源释放冲击波。

玩法：强调格挡时机、反击和站位，适合重武器、盾牌或防御反击型武器。

# 八、程序数据结构建议

第一版采用简单 JSON 即可，不必一开始就建立复杂数据库。

建议分成四类文件：

- `constellations.json`：二十八宿与四象信息。
- `star_officials.json`：星官目录及其所属天区。
- `build_units.json`：宿印、星官符文与效果参数。
- `boss_rewards.json`：Boss、掉落表和首次击败奖励。

示例：

```json
{
  "id": "xiu_jiao",
  "name": "角宿",
  "unit_type": "xiu_seal",
  "domain_id": "xiu_jiao",
  "quadrant": "east_azure_dragon",
  "capacity_cost": 2,
  "tags": ["charge", "pierce", "armor_break"],
  "effect": {
    "trigger": "charged_attack_hit",
    "actions": [
      {
        "type": "pierce",
        "extra_targets": 1
      },
      {
        "type": "apply_armor_break",
        "value": 15
      }
    ]
  },
  "set_links": [
    "official_jinxian",
    "official_tiantian"
  ],
  "first_clear_reward": {
    "guaranteed_units": ["xiu_jiao"]
  }
}
```

这里的效果字段是建议的数据接口示例，实际字段应根据游戏的战斗系统调整。

```json
    ]
  },
  "rarity": "uncommon"
}
```

建议将触发器、效果类型和数值分离，避免每一个组件都需要编写专用代码。程序只需识别通用效果，再由 JSON 提供参数。

# 九、第一阶段开发范围

不建议立即制作完整的 28 个 Boss 和数百个星官。

先完成一个能够验证核心玩法的最小版本：

1. 制作四个 Boss，分别代表青龙、玄武、白虎、朱雀。
2. 每个 Boss 提供一个核心宿印。
3. 每个宿提供两枚可获取的星官符文。
4. 实现五点星位容量和基础装配界面。
5. 实现本宿共鸣与四象共鸣。
6. 制作三套差异明显的武器 Build。
7. 测试不同组件是否真正改变了攻击行为，而不仅仅改变伤害数值。

验收标准：

- 玩家击败 Boss 后能明确感受到获得了新玩法。
- 同一把武器至少能构建出两种明显不同的战斗风格。
- 组件之间存在有效联动，不存在一个组件在绝大多数情况下都明显优于其他组件。
- 重复获取组件仍然有成长价值。
- 增加新星宿时，只需增加数据和对应内容，不必重写整个 Build 系统。

# 十、最终建议

这套系统最值得投入的地方，不是一次性制作二十八个 Boss，而是建立一个可以不断扩展的“星宿武装”框架。

**星宿提供核心机制，星官提供组合变化，四象提供流派方向，三垣提供高阶成长与挑战。**

如果这四层各自承担清晰的职责，玩家击败 Boss 获得的就不是一件普通装备，而是一个能够改变武器打法的构筑组件。

这会比单纯收集二十八套固定装备更有长期可玩性，也更适合后续持续增加星官、Boss、武器和套装效果。
