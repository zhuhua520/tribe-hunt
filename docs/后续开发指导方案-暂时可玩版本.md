## 1. 暂时可玩版本的目标

做出一个可从主菜单进入、可以重复游玩的俯视角 2D 单人远征原型：

主菜单 → 单人出征准备 → 普通波次战斗与波间构筑调整 → 在撤离节点决定撤离或继续 → 区域末段挑战野猪王 → 结果页。

目标是验证基本循环是否好玩、玩家是否能读懂战斗选择和 BOSS 攻击，不是完成长期经济或正式发行版本。当前项目已有主菜单、单人三波战斗、设置存档和两个临时模块原型；本方案在这些基础上扩展，不重做已完成系统。

## 2. 已确认方向

- **视角**：俯视角 2D。当前玩法代码已经是平面内上下左右移动；角色和敌人贴图仍是占位表现，尚未完成正式俯视角美术。
- **核心操作**：玩家移动和攻击，不加入主动技能。自动攻击保留为一种待对照的原型，可开关；自动与手动攻击都需要做小原型后再比较。
- **构筑基线**：沿用阶段 3.2 的两个样例模块、出征选择和波间调整。它们及 +20% 临时效果不代表最终数值、库存、槽位、掉落或成长规则。
- **撤离**：节点安排要通过原型比较；单人选择继续或撤离。合作投票不在本阶段实现。
- **地区 BOSS**：暂定野猪王，不加传说设定。玩家能围绕它移动并躲避范围攻击。
- **野猪王首版行为**：缓慢追近玩家；周期性蓄力直线冲撞，冲刺开始时锁定方向并给地面方向预警，冲刺后有收招时间；周期性蓄力震地，给出清楚的地面圆形危险提示后造成范围伤害。首版不做多阶段、召唤物、异常状态或复杂机制。
- **工作分工**：Cursor 负责玩法代码、可运行占位，以及 P6 的 UI/美术接入准备。最终视觉与立绘等待 Codex 后续制作，接入准备不提前画最终美术。
- **合作/联机后置**：P7 须用户确认后才恢复。2.2 两台设备局域网测试继续冻结；不接云服务器、Steam 好友邀请、公开房间搜索或正式 Workshop。
- **存档**：目前设置存档已存在。远征奖励、玩家成长、收藏、掉落和联机奖励规则未定，不在暂时可玩版本中写入成长存档。

## 3. 单人闭环的临时规则与边界

### 3.1 远征流程

- 保留现有三波普通敌人作为远征前段；波间构筑调整继续可用。
- 普通波次后按当前测试节奏打开撤离节点；选择“继续”进入下一段，选择“撤离”则以撤离结果结束本次运行。
- 三波普通敌人结束后进入野猪王遭遇。击败野猪王为本次远征胜利；玩家生命归零为失败。
- 每波开放与每两波开放都只作为对照配置，不提前定为最终节奏。对照配置应能复用同一套流程，不复制两套战斗实现。
- 不设置永久货币、奖励发放、死亡损失、收藏解锁或成长升级。撤离与击败 BOSS 只产生不同的本次结果，不改变存档。

### 3.2 野猪王实现边界

- 使用独立的 BOSS 场景/脚本或清楚分离的职责，不把 BOSS 特例塞进普通敌人脚本。
- 共享通用的生命、受击、死亡和结果接口；移动策略与攻击招式保持可组合。首版只实现追近、直线冲撞、震地三种行为，不造通用行为编辑器或复杂插件框架。
- 冲撞方向在蓄力结束时确定，冲刺期间不自动追踪玩家；让玩家能通过横向走位躲开。
- 冲撞方向与震地范围必须有地面预警；伤害判定发生在预警后，留出实际躲避时间。
- 视觉大体型、地面占地、碰撞范围、受击范围和招式范围分别表达。以地面锚点参与前后排序，避免身体贴图遮住玩家或攻击预警。
- 当前自动近战/远程攻击都应能对 BOSS 造成伤害。数值先取便于测试的临时值，明确标注为原型值。

### 3.3 结果与观察数据

结果页先显示可观察指标：

- 本局用时
- 击杀数
- 受到的伤害或受伤次数（实现时选择现有系统可稳定记录的口径，并在交接中写明）
- 本局结局：撤离、击败野猪王或失败
- 野猪王战斗结果；可以记录遭遇时长/是否击败，供原型比较

当前为单人原型，不计算联机伤害占比，不发放正式奖励，不把统计写入成长存档。若指标口径不能从现有事件可靠获得，应先记录实际可得数据，不得用估算值冒充。

## 4. 分阶段执行顺序

Cursor 每次只执行一个子任务，验证、更新进度与交接后停止；不得一次性执行整条路线。

### P1：远征结果与基础统计

**目标**：为现有单人运行建立本次运行内的结果数据，结果页显示用时、击杀、受伤和结局。  
**范围**：只记本次运行内数据；可复用现有结果页；不新做经济系统和成长存档。  
**验收**：重新开局会清零；胜利、失败路径显示相应结局；统计不会跨局残留；主菜单到三波战斗的现有路径仍可完成。

### P2：撤离节点节奏对照

**目标**：可在同一远征流程中对比“每波开放”和“每两波开放”。  
**范围**：增加最小继续/撤离面板；撤离结束本局并进入结果页；继续会推进现有流程。使用运行规则配置或清楚可切换的测试设置，不做两份复制场景。  
**验收**：两种节奏都能完整触发；撤离与继续结果正确；波间构筑调整仍可用；不发放奖励、不写成长存档。

### P3：野猪王最小遭遇

**目标**：将一只野猪王接入三波普通敌人之后，验证围绕大型 BOSS 走位和躲避范围攻击。  
**范围**：缓慢追近、可预警的定向冲撞、可预警的圆形震地；基本生命与受击反馈；击败/失败结果。攻击间隔、速度、范围等仅为临时原型值。  
**验收**：玩家能绕 BOSS 移动；冲撞和震地都能看清预警并实际躲避；冲撞不在启动后跟踪玩家；普通武器能造成伤害；BOSS 死亡后胜利，玩家倒下后失败。普通三波和波间构筑回归正常。

### P4：单人全流程闭环与试玩修正

**目标**：从主菜单完整走通准备、三波普通战斗、撤离/继续、野猪王、结果、重新开始/返回菜单。  
**验收**：撤离、击败 BOSS、玩家失败三种结局都能抵达结果页；统计结果合理；每条路径可重新开始；Cursor 提供操作步骤和已验证/待人工试玩的清单。玩家主观手感由用户试玩反馈，不把自动化跑通等同于“已确认好玩”。

### P5：自动/手动攻击对照（暂缓，不是已完成）

**状态**：2026-10-16 用户决定跳过本阶段，先做 P6 接入准备。P5 仍未实现，不能记成已完成。恢复时仍须先确认手动瞄准/选敌方式。  
**目标**：依照既有确认，对自动攻击和手动攻击做单人小原型对照，记录用时、击杀和受伤情况。  
**范围**：复用当前武器和远征基线；不加主动技能、不改联机。  
**门槛**：手动攻击的目标选择/瞄准方式仍未定。用户没有采用“一个攻击键、自动选择最近有效目标”，Cursor 不得自行换一种方案实现。现有自动攻击继续支撑已完成的单人闭环。

### P6：UI 与精灵接入准备，最终视觉仍由 Codex 后续制作

**状态**：P4 完成后直接进入。Cursor 只做替换挂点和界面结构准备。最终立绘、背景、图标和皮肤不在这一步绘制。  
**开始条件**：P1–P4 已完成。P5 暂缓不阻塞本阶段。

**工作范围（Cursor，接入准备）**：

- 检查主菜单、出征准备、战斗 HUD、波间构筑、撤离选择、野猪王血量/攻击预警和结果页。只有影响完整操作的功能缺口才补占位结构。
- 记录玩家、普通敌人、武器、野猪王和界面的现有挂点，见 `docs/UI与精灵美术交接清单.md`。
- 保持俯视角 2D 和已验证的 P1–P4 流程。不改战斗数值、攻击方式、撤离规则、奖励、存档或联机。

**后续（Codex，本阶段不执行）**：按清单替换俯视角精灵和界面视觉。野猪王使用单独贴图，身体不挡住玩家和地面预警。视觉是否好用由用户试玩决定。

**交付**：交接清单和路线更新。不交付最终立绘、背景、图标或皮肤。

### P7：恢复合作与联网验证

**开始条件**：用户明确同意恢复合作/联网。P6 接入准备完成，或之后的立绘完成，都不自动开始本阶段。此前 2.2 继续冻结。

**建议顺序**：

1. 检查既有本机双开 2.1 代码和单人路径，不重写已经完成的会话闭环。
2. 先确认本地合作与在线合作的排期顺序，再恢复对应的最小测试。
3. 用户提供两台设备后恢复 2.2 局域网联调，逐项验证移动、敌人、攻击、BOSS、撤离、结果与断开。
4. 局域网稳定后，再用云服务器和手动输入地址/端口做跨网络朋友测试。
5. Steam 好友邀请、公开房间搜索和 Workshop 正式功能继续单独排期；Workshop 保持占位。

当前网络模型是服务器权威状态同步，不是帧同步。恢复后以实测决定是否需要快照编号、插值、预测或其他改进；不预先做大规模网络重构或假定必须帧同步。

## 5. 当前未定项与处理规则

- **手动攻击的瞄准/选敌方式**：P5 暂缓，不是已完成。恢复 P5 前再讨论。不得把历史上未采纳的最近目标方案当成确认。
- **撤离最终节奏**：P2 只比较配置，不锁定最终规则。
- **野猪王数值、招式节奏和受击反馈**：先用可读的临时值，试玩后再调。
- **奖励、掉落、成长、收藏与存档**：留待远征风险/奖励规则确定后单独排期。
- **合作人数、同屏镜头、联机奖励和失败规则**：不在当前单人原型中擅自决定。
- **元素、星座完整效果、武器品质细则**：保留现有占位，当前闭环不扩写。

发现实现依赖某条未定规则时，Cursor 应指出具体阻塞和可独立完成的部分，不得静默替用户决定；不依赖该规则的工作继续推进。

## 6. Cursor 每个任务的执行约束

开始前阅读：

- .cursor/rules/godot-project.mdc
- 部落远征-完整设计方案-v2.md
- docs/Godot开发规范与约定.md
- docs/进度.md
- docs/交接文档.md
- docs/后续开发指导方案-暂时可玩版本.md

每次任务：

1. 检查 Git 状态并保留现有未提交修改；不重置、清理、覆盖或擅自提交/暂存无关更改。
2. 只做本次指定的一个子任务，写清目标、范围、不做事项和验收条件。
3. 遵循 Godot 4.7.2 及项目强约束：静态配置与运行时状态分离；脚本/节点职责清楚；输入经 InputMap；存档若未来加入则使用稳定 ID、版本化与校验；联机关键状态由服务器验证。
4. 执行项目规范要求的针对性验证并回归主菜单和单人路径；只记录实际跑过的验证。
5. 更新 docs/进度.md 和 docs/交接文档.md，包括改动文件、验证、未完成项、待用户试玩/决策事项和下一最小任务。
6. 给出清楚交接，完成后停止，不自动开始下一阶段。
