# TribeHunt：俯视角 2D 开发总路线与美术交付方案

版本：v1.0 · 编制日期：2026-10-18  
用途：交给 Cursor 按阶段实施；Codex 负责美术资源选型、制作与交付。  
状态：指导方案已编制；下列游戏开发阶段尚未因此完成或自动获准连续执行。

## 1. 目标、优先级与实施边界

最终目标以[游戏项目总控与 AI 开发导航手册](../参考文档/游戏项目总控与AI开发导航手册.md)中的已确认基线为准：俯视角 2D 像素动作游戏，探索、战斗、资源与技术进展、基地准备构成循环。玩家与装备应可成长，不同武器和敌人必须具有机制差异。

本方案将目标拆成三个交付层级：

1. **探索切片**：基地—林地外围—森林深处—野猪王空间，加上外围通往废弃设施的支路；场景往返、交互、碰撞和进度保存完整。允许暂用现有木棍、弹弓和占位敌人。
2. **动作与装备版本**：剑、重锤、长弓、单发火铳；闪避、攻击阶段、统一伤害、护甲破甲；可组合角色、换装 UI 和成长；普通、精英与区域 Boss 行为可区分。
3. **后续内容验证**：遗迹 Boss 和一个星宿 Boss 原型。完整星宿 Build、开放世界、自动化基地、联网扩展另行立项，不在前两层验收中强行加入。

### 1.1 信息优先级

1. 用户最新明确指令。
2. 总控手册中明确的已确认设计；用户已再次确认俯视角 2D。
3. 本方案的阶段范围、依赖与交付安排。
4. 各专题文档中与上述基线一致的细节。
5. 旧 v2、P1–P7 路线和历史记录，用于理解旧原型及未解除的约束。

实际实现状态以代码、场景和验证证据决定；文档优先级不允许把计划写成已实现。下面的文件路径和新增文件名是范围建议，实施前要核对已有等价能力，避免照目录示例复制系统。

### 1.2 对后续执行的授权解释

用户本次要求的是指导方案，不是立即开发全部功能。Cursor 接到“执行 Sx”后只完成该阶段；默认每次完成一个可验收子阶段后停止。阶段内常规实现取舍自主完成，不为命名、文件拆分反复询问；涉及标为待决定的玩法规则才暂停相关部分。

后续批准某一阶段时，该阶段明确需要的最小功能取代旧路线中对应的临时禁令。例如 S3 获准后可以做地图进度保存，S7 获准后可以做一种固定 Boss 奖励；这不等于开放随机掉落经济、完整技术树或联机奖励。

## 2. 状态标签与审查基线

所有报告使用下列标签：

- **CONFIRMED 已确认设计**：来源明确的目标，不代表已经实现。
- **PROPOSED 建议方案**：本方案提出的实施办法或试验值，不能转写为用户最终决定。
- **TBD 待决定**：必须在对应阶段前解决的问题。
- **CONFLICT 冲突**：列出两方来源、影响和处理方式。
- **VERIFIED 已实现且有验证证据**：说明测试版本、日期、日志和覆盖范围。
- **UNVERIFIED 已实现但未验证**：代码存在，相关运行行为缺少证据。
- **MISSING 尚未实现**：检查相关代码和场景后未找到目标能力。
- **UNKNOWN 未知**：检查范围或证据不足。

## 3. 当下冲突的处理清单

### C1：横版动作假设

来源：玩家核心设计中的左右移动、跳跃与空中移动；旧地图方案的平台跳跃；武器动画清单中的跳跃下落。

处理：保留原文作为历史参考，当前切片使用平面二维移动。跳跃、攀爬、高度差与跳跃下砸不进入本方案必做项。攻击方向、碰撞和地图空间必须按上下左右及斜向移动验收。共享伤害、武器差异和破甲规则可以沿用。

### C2：波次远征与探索地图

处理：旧 Arena 保留为回归和数值实验场；新探索入口明确标注，不复用一个含糊的“野猪林”按钮指向两种模式。探索区不强制三波、波间构筑或撤离投票；复用角色、武器、敌人和事件接口，不把 WaveManager 改成全世界控制器。

### C3：旧禁令与新保存需求

处理：按照本方案阶段逐项开放必要的持有物、区域状态和奖励保存，设置存档独立。旧“当前不做成长存档”不再永久阻止探索切片；复杂经济、联机归属、随机词条仍后置。

### C4：自动攻击与动作武器

处理：旧自动武器继续用于 S1–S3 地图验证。四类动作武器不能只换皮或伤害值；进入 S4 前确认手动瞄准方案。不得把用户过去未采用的“一个攻击键、最近有效目标”重新当成已确认手动方案。无确认时停止 S4 的依赖部分，仍可做地图与美术协议工作。

### C5：星宿方案互相矛盾

处理：武器绑定星位、角色星盘、一宿两官、随机副词条、共鸣规则均不进入当前实现。已有两个测试模块保留为旧原型内容；不删除，不扩充成正式体系。星宿 Boss 的主题攻击可在后期独立验证，不依赖 Build 完成。

### C6：美术旧规格与现有 LPC

处理：以现有 LPC 接入为技术基线，Codex 在 A0 确认视觉样板；64×64 是当前玩家单帧协议，不是要求所有怪物、建筑和图块都为 64×64。旧“所有角色单帧”“32px 玩家”“村落纯几何”的说明不得指导新制作。保留原始素材和授权记录，不批量覆盖旧图。

### C7：验收与进度漂移

处理：交接维护一个当前快照，进度保留历史事件；132 是旧结果，142 是后续现存日志。图层接口通过不等于完整换装；Boss 角色场景不等于独立 Boss 地图；样例 Resource 不等于正式装备库存。

## 4. 工程复用与最小接口原则

### 4.1 应复用

- `SceneFlow`：扩展目标入口和返回上下文，不重复创建菜单导航管理器。
- 现有玩家移动、生命和信号：按新地图需求局部解耦，保持旧竞技场入口。
- `WeaponDefinition`、`CombatTargeting`、`take_damage`：逐步承接攻击参数和命中事件，不要求一次替换全部生命组件。
- Boss 自身行为脚本：独立战斗场景接入其信号，不把奖励、存档写进攻击动作代码。
- 外观 profile/layer：扩展状态图集和装备状态映射，保留现有同步协议。
- 现有回归测试：补用例，不无条件安装第二套测试框架。
- `SettingsStore`：保留独立设置；只复用已验证的字段校验经验，不直接复制其写盘流程作为可靠进度存档。

### 4.2 只在需要时补的职责

- 场景入口：目标场景 ID、目标出生点 ID、切换去重、无效入口回退。
- 玩家状态：生命、已持有物、已装备物、必要成长数据；不得由视觉节点充当唯一状态源。
- 世界状态：稳定区域/对象 ID 对应的门、奖励、Boss 和检查点状态。
- 进度写盘：版本、校验、可靠提交、备份及恢复。
- 命中事件：来源、攻击实例、目标、必要的伤害/破甲数据；按阶段增加实际需要的字段。

这些是职责，不是要求新建五个 Autoload。先检查所有者和生命周期，再选最小实现。推荐按场景重建玩家并从同一状态恢复，符合现有切换方式；不要未经评估将玩家变成永久全局节点。新增单例必须说明为何普通场景对象无法满足需求。

碰撞层先写清玩家、敌人、实心地形、投射物/攻击、交互探测的关系，再配 mask。绘制排序与物理碰撞独立；不直接用整张树冠或角色透明轮廓生成地面阻挡。

## 5. 需要决定的事项及到期节点

只在影响当期实施时询问，其余保留 TBD。

- **D1，S4 前：瞄准与攻击输入。**建议优先比较鼠标方向瞄准与独立方向输入两种小原型；自动攻击是否作为可选辅助另行比较。不要默认为最近目标手动攻击。S1–S3 不依赖此决定。
- **D2，S2 前：资源刷新。**建议首个验证资源明确为一次性测试拾取，不推导全世界资源永不刷新。可重复资源规则后定。
- **D3，S3/S7 前：保存与失败恢复。**建议首切片采用明确安全点保存；死亡回最近安全入口，永久解锁保留，不额外扣资源；Boss 失败重置战斗、已领唯一奖励不重发。此为推荐，用户确认前不得作为正式玩法写入。
- **D4，S9 前：装备语义。**外观层 ID 不等于装备槽；首版建议一把当前战斗武器加按部位穿戴，切换能力不锁死最终携带槽数。护甲部位、内衣状态和库存容量只决定本阶段所需范围，不恢复旧四格背包。
- **D5，S10 前：成长与技术。**先确定有限测试等级区间、一项技术解锁和数据口径，不先锁死长期等级上限或完整科技树。
- **D6，A0：美术基准批准。**Codex 提供同屏玩家、普通敌人、树木/地面样板；用户确认风格，Cursor 只做接入和技术验收。

动作帧数、速度、伤害和无敌时长属于原型调参，可以使用明确标注、可配置的测试值，不必每项询问，但不能写成最终平衡数值。

## 6. Cursor 分阶段实施路线

每阶段报告都要包含：起始状态、实际修改文件、实际运行的命令与结果、人工验收项、未验证项、下一阶段依赖。以下“验收”是未来通过条件，不是现状声明。

### S0：建立可重复的工程基线

- 依赖：本方案获准作为开发路线。
- 最小闭环：从主菜单进入旧竞技场，验证失败、胜利、重开和撤离回村可继续使用。
- 修改范围：只修复阻挡启动/回归的已复现问题；必要时补 `tests/` 中明确缺失的基线用例和文档，不加入玩法。
- 验收：记录引擎路径和版本；现有回归无错误；至少人工走一次真实移动与战斗路径；历史 Safe save 问题若仍出现记录影响，不关闭安全功能掩盖错误。
- 停止条件：若代码或资源加载失败，先局部修复，不进入地图开发。未跟踪文件逐项识别，用户改动保留。

### S1：基地与林地外围往返

- 依赖：S0；使用灰盒，不等待正式地图美术。
- 最小闭环：基地出发→外围移动→返回基地，方向正确且只有一个玩家。
- 修改范围：`scene_flow.gd`、村落入口、新外围场景、最小入口/出口逻辑、玩家地图边界及碰撞配置；必要的状态传递只含当前生命和入口上下文。
- 验收：连续往返至少十次；双向出生点正确；无重复玩家、立即反复传送或墙内出生；墙壁阻挡和相机边界实测；一棵占位树前后遮挡正确；旧 Arena 可独立运行。
- 不做：森林深处、Boss 奖励、完整背包、程序化地图。
- 美术：A0 可并行，正式资产不阻塞此阶段。

### S2：外围支路、一次拾取与地图战斗

- 依赖：S1、D2。
- 最小闭环：进入外围→绕开或击败一个现有敌人→在支路获得一种资源→返回基地查看数量。
- 修改范围：外围布局、一个资源节点、最小交互输入与反馈、进程内持有物/区域状态；敌人地形碰撞；木棍隔墙检查和石弹路径碰撞适配。
- 验收：同一对象重复触发只增加一次；场景往返不重复领取；敌人可达、不穿墙；攻击被实心墙正确阻挡；石弹在同一帧先遇墙时不能命中墙后敌人，高速经过薄目标不漏判；暂停后交互不继续执行。
- 不做：随机掉落、资源经济或复杂寻路。只有已复现障碍卡死且简单布局/行为不足时，再评估最小导航。
- 美术：可接 A1 的一组环境样板，缺图用占位。

### S3：最小进度保存与恢复

- 依赖：S2、D3 中保存方式。
- 最小闭环：拾取→安全保存→退出进程→重新进入→位置与资源正确恢复。
- 修改范围：`scripts/save/` 中独立进度数据与读写、当前玩家/区域状态、继续入口、存档测试；保留独立 `settings.json`。
- 验收：schema_version、稳定 ID、字段类型和范围校验；正常保存、损坏主文件、主文件缺失但备份存在、较新版本拒绝覆盖、未知内容 ID 均有结果；临时文件完整验证后可靠提交，模拟提交失败时至少有一份可恢复进度。
- 奖励一致性：物品增加与领取标记在同一逻辑事务/同一保存快照中提交；失败后不会出现“资源丢了但已领取”或“物品已增加但可再次领取”。
- 验收还包括：测试使用隔离 user 数据，不触碰真实玩家进度；重启进程验证，不能只在一个 SceneTree 中重载场景。
- 不做：云同步、账号、多档位、加密、在线奖励归属。

### S4：一个手动攻击与闪避控制原型

- 依赖：S3、D1；A2 动作协议先交付，画面可暂用调试形状。
- 最小闭环：玩家移动、瞄准、一次攻击、闪避避开测试攻击，受击后仍能恢复控制。
- 修改范围：InputMap、现有玩家状态、武器输入入口、外观状态选择；保持旧自动战斗模式可测试。
- 验收：四方向和斜向移动；前摇/生效/后摇清晰；无耐力消耗；不能用连续闪避跳过不可取消阶段；受击、死亡、暂停、换场时动作状态不残留；输入缓冲不会无限排队。
- 不做：完整四武器、自由技能栏、最终动作数值。记录选中控制方案与待调整手感。

### S5：剑与野狼最小动作闭环

本阶段分 S5a、S5b，必须分别验收，不一次完成两个大系统。

**S5a：剑。**复用武器定义和伤害入口，增加关键帧区域、相邻采样扫掠、攻击实例目标去重；接入三段普通连击及单独蓄力斩。最小闭环为玩家可对两个测试目标连击、取消和落空。验收：前摇/后摇不伤害；一段命中多个目标但每目标一次；下一段能再次命中；转向、低物理更新频率/高移动速度测试不明显漏判；视觉与范围吻合。范围限玩家、近战、必要攻击数据及测试。

**S5b：野狼。**基于现有敌人接口增加有限察觉、追击、撕咬前摇、生效、恢复、受击与死亡；巡逻只做一个简单范围。最小闭环为外围一场可通过观察与走位应对的遭遇。验收：离开活动范围不无限追逐；攻击持续重叠不重复结算同一攻击实例；死亡事件一次；不穿墙、不在墙内出生；剑可正常击败。

- 美术：A2 玩家剑动作、A3 野狼；接入前先完成调试判定可视化。未交正式图可验证逻辑，但不能宣布动作表现通过。

### S6：护甲破甲与重锤

分 S6a、S6b 独立验收。

**S6a：普通装甲测试目标。**在现有伤害流程中增加可选护甲/破甲；最小闭环为连续攻击→达到阈值→破甲窗口→恢复。验收：触发那一击按命中前防护结算；破甲期间不积累下一轮；结束重置；无甲目标行为不改变；死亡不再触发破甲。不加入所有敌人的多部位系统。

**S6b：重锤。**增加独立普通重击和蓄力动作及较高破甲贡献，复用 S5 判定。最小闭环为同一装甲目标下剑/锤各完成一次战斗。验收：锤在节奏与风险上可辨，不能只加伤害；蓄力可按确认规则取消，生效阶段不能绕过承诺；不默认每击打断 Boss。需要时接 A2 重锤动作。

### S7：森林深处与独立野猪王场景

分 S7a 场景连接、S7b 战斗与奖励；依赖 S3、S5、S6、D3。

- S7a 最小闭环：外围→深处→Boss 入口→返回，入口、相机和地形通过；深处用现有敌人组合形成更高威胁，不增加新精英作为依赖。
- S7b 最小闭环：进入→躲避冲撞/震地→击败→取得一种固定奖励→回基地→重启后检查状态。
- 修改范围：新增深处与 Boss 地图、现有 Boss 脚本的地形适配和可选护甲、局部遭遇协调、出口、世界状态及奖励事务。旧 WaveManager 保留竞技场用途。
- 验收：Boss 生成不贴脸造成无法反应伤害；冲撞方向锁定、墙体处理正确；退出/失败后按 D3 重置；胜利不再强制旧竞技场结果阻断探索；重进与读档不能重复发唯一奖励。
- 美术：A3 野猪王体型/动作，在判定稳定后接入；先验地面锚点与预警可见性，再定细节。

### S8：废弃设施与第一份技术资料

- 依赖：S3；可在 S7 后实施，不以玩家击败 Boss 作为地图门槛。
- 最小闭环：从外围支路进入设施→操作一个装置开门→取得资料→回基地→重启检查。
- 修改范围：一间室内地图、一门一开关、技术资料 ID、少量 UI 反馈；复用交互与存档。
- 验收：Boss 未击败也可进入；门/装置/资料状态恢复一致；不能重复领奖；资料先作为稳定解锁标记，不提前生成整棵技术树。
- 美术：A4 室内地面、墙、门、装置与资料图标；无需等待遗迹 Boss 美术。

此时可进行“探索切片验收”：五场景可走通、资源和 Boss 状态保存、失败恢复正常、设施有意义；只完成此层不代表四武器、完整换装或成长已经完成。

### S9：最小装备状态与实际换装

分 S9a 状态与武器切换、S9b 服装 UI，依赖 S3、S4、D4。

- 最小闭环：基地查看持有装备→装备/卸下→外观及战斗同步→进入外围→返回或重启后保持。
- 修改范围：最小物品/装备实例数据、装备面板、玩家状态、外观映射、武器启停；复用已有 AppearanceLayer。
- S9a 验收：换武器停止旧攻击，冷却/蓄力状态按明确规则处理；视觉武器与实际攻击为同一装备来源；空手状态合理；不能通过切换跳过装填或冷却。
- S9b 验收：身体、独立内衣、上衣、裤装、鞋和护甲的测试组合可穿脱；旧层立即移除；预览与场景共享同一装备状态；四方向移动/攻击不漂移；失效资源不清空原装备；装备只通过稳定 ID 存档。
- 不做：随机词条、耐久经济、制作树、无限部位槽。A2/A5 交付对应透明图层，不能把整张合成人物称为可脱卸服装。

### S10：混合成长与一项技术用途

依赖 S8、S9、D5；分经验成长与技术解锁两个小任务。

- 最小闭环：一次合法击杀获得经验→升一级→生命/基础攻击适度变化→资料解锁一个可实际使用的装备或制造能力→保存恢复。
- 修改范围：最小经验/等级配置、角色派生属性、装备防御读取、一条技术解锁及 UI；不改共享 Resource。
- 验收：等级不开放自由加点；同一击杀不重复奖励；满血/受伤时升级的生命更新规则明确；装备贡献与等级贡献可分别测试；敌人不随玩家等级全局缩放；回低威胁区域能感受成长。
- 技术验收必须有可用结果，例如解锁一件测试装备，不能只出现“已解锁”文字。所需成本作为有限测试配置，不推导完整经济。

### S11：长弓

- 依赖：S4、S9，复用 S2 投射物路径检测；A6 弓动作。
- 最小闭环：装备弓→快速射击或蓄力→箭矢飞行→命中/被墙挡→更换武器和读档正确。
- 修改范围：弓攻击数据、蓄力/释放状态、箭矢、外观及少量测试，不重写远程框架。
- 验收：到发射时刻才生成箭；方向符合 D1；默认首个有效碰撞停止；移动射击与取消明确；蓄力不跨暂停/换场意外释放；与剑/锤的体验可区分。
- 弹道重力在俯视角中的表现尚未确定，首轮建议直线；不得直接沿屏幕 Y 轴套用横版重力。

### S12：单发火铳

- 依赖：S11；A6 火铳动作和特效。
- 最小闭环：装填完成→开火→后坐→装填→再次开火，期间可移动和按规则闪避。
- 修改范围：独立装填状态、射击时序、高速弹体、反馈及测试。
- 验收：未装填不能开火；切武器/闪避不直接完成装填；装填进度保留或重置必须明确记录；高速弹体不穿薄墙和薄目标；同帧按路径最先碰撞结算；较高单次破甲不意味着无条件打断 Boss。
- 不做：复杂弹药库存和制作；如确需弹药限制，先单独确认，避免无弹导致原型不可测试。

### S13：精英老虎与狼王

依赖 S5、S10；每次只实现一种，复用生命、命中、活动区域和死亡接口。

- 老虎闭环：发现玩家→可预警扑击→落空恢复→玩家反击→击败并获得已定义奖励。
- 狼王闭环：强化追击或有节奏的连续攻击→可读恢复窗口→击败；不复制野狼后只加生命。
- 修改范围：各自数据、少量专属状态、一个测试遭遇、A7 资产。
- 验收：普通野狼/老虎/狼王/野猪王同时列入试玩清单；四类敌人行为可辨；各武器都有可行打法；扑击不会穿墙或无限转向追踪；奖励复用既有规则。

### S14：完整动作与装备版本验收

- 最小闭环：从基地装备准备→完整五场景探索→不同武器战斗→失败/成功→返回→保存恢复，连续两轮。

- 验收：S1–S13 的已开放目标逐项检查；攻击/受击/死亡动画、四方向装备、奖励事务和成长均有证据；人工验证手感与遮挡；正式目标平台导出单独验证，不能用编辑器运行替代。

### S15：遗迹 Boss 与弱点（后续独立批准）

- 依赖：S14。
- 最小闭环：机械守卫防御→预警攻击→核心暴露→玩家实际命中弱点→击败→技术奖励保存。
- 修改范围：一个独立遭遇、可选弱点区域、命中优先级、Boss 数据、A9 美术。
- 验收：未暴露弱点不生效；实际接触位置决定收益；区域重叠结果稳定；普通敌人不被迫拥有多部位。永久部位破坏仅当本 Boss 机制确实需要时另拆子任务。

## 7. Codex 美术交付计划

美术由 Codex 负责选型、生成或复用、质量检查和交付；Cursor 负责资源接入、动作事件、碰撞和运行验证。用户已授权将美术安排进阶段，但本文件不启动无人值守的后台生产。Cursor 到交付点时在交接中列出需求，用户将该需求交给 Codex；不能假设另一个工具会自动接单。

### 7.1 分批交付时机

- **A0，S1 前后：视觉与规格样板。**现有 LPC 玩家、一个普通敌人、树木、地面同屏对照；确定视角、像素密度、色板、阴影、脚底锚点。先交规格和一小组样板，不制作完整地图。
- **A1，S2：外围最小环境包。**地面、路径、树干/树冠、岩石、资源节点。场景摆放和碰撞由 Cursor 实现，不把整张背景画当可编辑地图。
- **A2，S4–S6：玩家动作和图层协议。**先一个方向、一个近战动作做技术样本，接通后扩四方向；剑和重锤分批。身体、服装与手持武器共享帧坐标与时间。先保证已穿戴组合完整，再扩衣服数量。
- **A3，S5b/S7：野狼与野猪王。**先基准体型/地面锚点，再交待机、移动、攻击、受击、死亡及必要预警素材；Boss 动作与程序判定时间共同校准。
- **A4，S8：废弃设施小包。**一套墙地、一门一装置、一资料图标；验证门的开闭状态和遮挡。
- **A5，S9：换装验证包。**独立身体、内衣、上衣、裤装、鞋、护甲与当前武器；优先复用授权清楚且匹配协议的 LPC 图层。每个部位只需足够验证替换/卸下的样例，不提前生产大量装备。
- **A6，S11/S12：弓和火铳。**四方向举持、蓄力/发射或装填、箭/弹、命中反馈；动作中手部与武器一致，不能只增加飘在角色旁边的武器图。
- **A7，S13：老虎和狼王。**逐个交付，先确保动作轮廓能区分敌人，再完善细节。
- **A8，S14：切片统一。**统一实际使用的地面、建筑、敌人、图标和 HUD；未使用资产不纳入大批换皮。
- **A9，S15/S16：机械与星宿专题资产。**仅在对应玩法原型通过后制作。

### 7.2 资产交付契约

每批交付至少提供：稳定 asset_id、来源/授权及上游版本、用途、原始图与最终图路径、像素尺寸、单帧尺寸、方向顺序、动作名称、帧数、每帧时长、循环/单次、脚底/握点坐标、图层顺序、预览和未通过项。攻击生效事件由 Cursor 与动作数据共同定义，不只凭图片文件名推断。

现有 profile 是技术起点：`ulpc_walk_v1`、9×4、64×64、down/left/right/up。攻击等动作可使用不同图集，但同一动作的身体和装备必须共享协议；禁止逐层独立裁切、独立缩放或独立底部对齐。保持固定根锚点；大武器必要时统一扩大该动作所有层的画布，不压缩角色比例来塞进格子。

地图交付必须区分地面、阻挡物、装饰和前景；树干与树冠是否拆分取决于遮挡需求。图块尺寸先做小样拼接再确定，不从角色 64px 推导图块也必须 64px。游戏碰撞依据地面占地，不从美术外轮廓自动认定。

### 7.3 美术验收

- 视角符合俯视角，不能混入纯侧视平台动作帧。
- PNG 透明信息真实；检查索引色透明度或 RGBA，而非仅凭文件扩展名。
- 相邻帧体型、脚底、手部与装备位置稳定；动作可读，不用简单旋转一张图替代所有方向。
- 最近邻显示、像素边缘与色板一致；无误加抗锯齿或烘焙棋盘背景。
- 在游戏真实视口和缩放下预览，包含树前树后、背面武器、大型敌人和地面预警。
- 攻击范围与有效帧可对照；装备开关与场景/预览同步。
- 原始图和旧版本保留；只将已接受的最终资源接入场景。

Codex 交图不等于运行验收；Cursor 接通代码不等于美术认可。二者分别报告，缺任一项时标记未验证。

### 7.4 工具选择与安装边界

- 首选现有 `imagegen` 生成/编辑位图，LPC 复用支撑玩家分层资产；现有 Godot MCP 和 efficient-game-dev 足以开始开发。
- Sprite Pipeline 是独立精灵动画的优先候选，使用前保留其共享脚本路径。默认逐帧裁切/底部对齐不适用于 LPC 装备层，不能直接处理分层资产。
- Agent Sprite Forge 仅作为地图、独立怪物的试验候选；先锁定版本并用一个真实样例验证。视频路线依赖 FFmpeg，不能因安装 Skill 就假定视频服务、预算或导出兼容性已经具备。
- Assetelier 和广泛的 Godot 模板 Skill 暂非必要；不同时安装重叠流水线，不用模板覆盖现有玩家/存档。
- 本机已检查 Python 3.14.7、Pillow 12.2.0、NumPy 2.4.4、Node 24.13.1；未发现 PATH 中的 FFmpeg/Aseprite/Godot，Godot MCP 可定位 4.7.2。依赖存在不代表候选脚本已在本机通过。

## 8. 验收证据与回归策略

### 自动验证

继续使用当前回归入口，按变更补充场景切换、真实物理运动、攻击扫掠、物品与奖励事务、独立进程存档恢复。测试不得只调用命中回调就声称物理碰撞通过；不得直接扣死 Boss 就声称招式可躲避。
