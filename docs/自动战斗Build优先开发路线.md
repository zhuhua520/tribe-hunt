# TribeHunt：自动战斗、Build 与内容扩展开发路线

版本：v2.0 · 日期：2026-10-20  
用途：Cursor 后续开发的当前施工入口。替代旧 S0–S16 的实施顺序；旧记录保留。  
状态：用户已确认转向自动攻击、Build 优先、功能占位美术，并确认角色级一核心两辅助。R0–R12 自动验收已于 2026-10-20 完成；导出包、20 分钟窗口和人工两轮未做。各阶段的容量和数值是首版建议。

## 1. 这次调整解决什么问题

玩家攻击动画的制作成本与当前效果不匹配，继续围绕手动连击、蓄力和分层动作投入，会阻塞武器、Build、掉落和地图。新路线把“选择与组合”作为主要乐趣，把自动战斗作为验证组合的载体。

目标闭环：

选择武器和 Build → 进入区域、走位避险、自动攻击 → 看见组件效果 → 击败敌人获得不同战利品 → 查看、比较、装配 → 回村保存 → 带着新组合探索更高威胁区域。

### 1.1 用户已确认的方向

- 保留俯视角、探索、区域战斗、资源获取、基地准备与进度保存。
- 玩家攻击改为自动化；当前不制作、不依赖玩家攻击动作动画。
- 优先建立并展示 Build，增加武器、敌人、场景和掉落，完善 UI。
- 美术首先满足功能可读与可替换；允许修改风格，使用授权明确的现成资源或几何占位。
- 日常测试直接加载目标场景，不从开始场景反复走流程。

### 1.2 对旧目标的具体处置

- **保留并复用**：移动、闪避、受击、死亡、地形碰撞、攻击实例去重、投射物扫掠、护甲破甲、场景入口、背包、存档。
- **替换**：玩家鼠标瞄准、点按连击、按住蓄力、攻击锁移动/朝向 → 自动选敌、自动释放、冷却/装填节奏。鼠标保留用于 UI 和物品详情。
- **停止投入**：逐武器四方向攻击图集、身体服装武器逐帧对齐、完整换装动作、以 A0 风格定稿作为玩法前置。现有素材与代码不批量删除。
- **继续要求**：攻击范围与效果一致，投射物不能穿墙；敌人预警、生效、恢复必须可读。“不做攻击动作”不等于无判定、无反馈或取消敌人攻击逻辑。
- **解除旧限制**：Build 不再整体暂缓；组件装配、机制触发、实例掉落、构筑存档进入主线。
- **仍后置**：联机、云服务、Steam/Workshop、完整二十八宿内容、元素反应、自由加点、大世界、复杂经济和最终美术生产。

### 1.3 方案建议与确认边界

下文建议首版用“一把当前武器 + 一套角色级 Build（1 核心 + 2 辅助）”，并准备 3 核心、6 辅助、4 类武器。用于限制首轮工作量，**不是已确认的最终携带槽、内容上限或平衡值**。

Cursor 可以先执行不依赖装配结构的 R0–R3。进入 R4a 前只需确认：采用本文件的角色级一宿两官首版，还是改成其他装配模型；无需同时追问后期经济、美术和全部星宿。阶段批准时已明确采用该方案的，不重复询问。

## 2. 当前工程事实与需要修复的断点

以下来自 2026-10-20 的文件检查，不是本轮运行测试结果。

### 2.1 已有可复用基础

- 实际玩家主入口是 `scenes/player/player.tscn`；Arena、外围和动作试验场均引用它。`scenes/combat/player.tscn` 仍存在，不能误以为它是唯一玩家或直接删掉。
- `player_action_controller.gd` 已有手动剑三段、蓄力、闪避、输入缓冲；`melee_attack_volume.gd` 有几何采样与扫掠，可以复用几何工具，不必保留动作驱动方式。
- `melee_weapon.gd`、`ranged_weapon.gd` 是自动木棍和弹弓，受 `SettingsStore.auto_attack` 控制，默认关闭。它们不是“当前装备武器自动释放”系统。
- `combat_targeting.gd` 有存活目标过滤、最近可见目标、地形视线检查和 `hit()`；有 `receive_hit` 的目标走护甲，否则走 `take_damage`。
- `BuildRunService` 仅处理旧 Arena 样例模块，按类别修改伤害、冷却、范围、弹速；不保存正式 Build，也没有完整组件事件机制。
- `data/items/items.json` 已有两把剑、一种材料；`data/effects/effects.json` 描述两种手动攻击方式。`ItemCatalog` 已连接背包；旧测试材料、兽皮仍从 `.tres` 读取。
- `ProgressState` 目前主要保存物品数量、已领取对象与村落入口；`ProgressStore` 的 `schema_version` 为 1。尚无随机组件实例、Build 预设、装备状态或图鉴存档。
- 村落、外围、旧三波 Arena、动作试验场可从各自场景入口加载；已有普通野兽、野狼行为、野猪王原型、装甲测试目标。
- 现有城镇房屋/树已独立成场景，玩家用 `hunter_sheet.png` 与 `hunter_sprite.gd`。LPC 留作夹具与历史资源，并非当前玩家运行外观。
- 背包和地上物品详情已存在；店铺仅展示目录，不能交易；开发者菜单可生成物品/木桩，不能代替正式装备入口。

### 2.2 不能跳过的工程断点

1. **武器数据双源**：物品表 `attack` 目前用于说明，实际剑伤害来自 `weapon_sword.tres`。必须统一，不能让 UI 与命中数值不一致。
2. **攻击通路并存**：手动剑与自动木棍/弹弓可能同时运行。新路线要求只让已装备武器生效，避免隐形额外输出。
3. **命中成功不等于有效伤害**：当前 `Targeting.hit()` 返回目标可调用与否，不能直接作为吸血、击杀、破甲触发的可靠依据；必须返回实际结算结果。
4. **实例与计数混用**：数量字典适合材料，不足以存两件同名但词条不同的组件；不能按显示名或 definition_id 覆盖实例。
5. **UI 新规范未覆盖所有旧页**：旧 `build_adjustment_panel.gd` 仍用代码拼页；在替换该页时迁移为场景和行组件，不做全项目 UI 重写。
6. **回归启动方式漂移**：旧文档写过窗口版不等待，当前脚本仍用 `&` 调用引擎。本轮只核对路径：`D:\Godot_v4.7.2-stable_win64_console.exe` 存在，`D:\godot\Godot_v4.7.2-stable_win64.exe` 不存在；没有运行版本命令。R0 必须重新定位并核实版本、等待和退出码。
7. **历史结果**：交接最新记载 `tmp/regression8.log` 为 327/0，部分真实窗口未做。本次没有重跑，不将该数字当作新路线验收。

Git 起点为 `c2a487f`；工作区已有四个 `.import` 修改、一个脏的临时素材来源子目录及未跟踪的 `动画资源整合/`。全部保留，不将这些变化混入本次文档修改。

## 4. 新版本的目标与完成标准

### 4.1 第一里程碑：能玩出 Build 差异（R0–R5）

玩家在现有城镇与外围间，能够通过正式 UI 装备武器、选择并保存 Build。至少有两套机制不同的组合；HUD、触发提示和测试统计能解释“为什么不同”。移除核心后，额外效果确实消失。回村保存并重启后恢复同一套配置。

不要求先拥有四种武器、五张地图或精美 UI。先证明构筑值得玩，再扩充内容。

### 4.2 第二里程碑：值得探索和换装（R6–R10）

建议首版内容规模：

- 4 类武器：剑、重锤、弓、火铳；每类先 1 把功能完整，之后剑/弓各加 1 个机制变体，共约 6 个条目。
- 3 种核心与 6 种辅助，支持跨类别组合；两条随机副词条在 R6b 才加入。
- 至少 6 种可辨战斗定位：普通野兽、野狼、装甲单位、远程机械单位、精英扑击者、野猪王。老虎/狼王可按素材与机制需要分批扩展，不能用同 AI 换色充数。
- 5 个场景连通；外围产基础素材，深处产核心/辅助，Boss 产首次关键奖励，设施产技术或特殊武器。
- 武器、材料、组件、图纸/解锁四类掉落，有不同用途与来源说明。

这些是首版验收样本预算，不是最终世界全部内容。

### 4.3 第三里程碑：可交给他人试玩（R11–R12）

玩家不借助开发者菜单，可完成两轮探索—构筑—战斗—收益—回村；可读档恢复、比较组件、查看来源和触发效果，知道下一步去哪里。目标平台导出包需要独立验收。

## 5. 自动战斗契约

### 5.1 输入与攻击调度

- 移动、闪避、交互、背包、暂停沿用 InputMap。保留现有无耐力闪避，但不自动增加自动走位、自动拾取或寻路。
- 战斗区自动攻击为默认核心行为；村落、暂停、死亡、结果态和换场期间不启动新攻击。
- 首版建议选择范围内最近且无遮挡的有效敌人；同距采用稳定的实体序号作次序，避免抖动。锁定到一次攻击完成；目标失效则取消该次或下一轮重选，不向已释放节点回调。
- 近战在释放时复核范围/遮挡；远程按发射时方向生成独立弹体，默认不追踪、不瞬时必中。制导属于后续明确机制。
- 玩家移动不因自动攻击被旧手动动作状态强行减速；朝向跟移动或最近有效朝向，攻击特效独立朝向目标。
- 冷却是数据时序。暂停冻结时间；换武器/Build 不能清零冷却刷爆发；初版在村落/试验场换装，进入战斗使用配置快照。
- 闪避期间首版暂停新攻击，旧投射物继续；受击/死亡清除待释放近战，既有伤害事件只结算一次。不得让旧手动缓冲在 UI 关闭后补打一刀。

### 5.2 表现的最低标准

- 剑：短扇形/弧光；锤：地面冲击圆与破甲提示；弓：可见箭矢；火铳：短枪口闪光、弹道与装填进度。
- 角色本体可只待机/走路；不播放攻击帧仍须有完整战斗功能。
- 敌人有预警形状、生效变化、命中闪烁、死亡淡出和掉落反馈。颜色必须配合形状/图标，不能只靠红绿区分。
- 特效使用的范围参数与实际判定同源；图像资源丢失时用几何/文字兜底。

## 6. Build、装备与实例契约（首版建议）

### 6.1 装配归属

- 一套角色级预设：`build_id`、名称、当前武器 ID、核心实例 ID、两个辅助实例 ID；多个预设只激活一套。
- 核心必选才算有效 Build；空配置时允许玩家用基础武器，UI 提示“未成型”，不软锁游戏。
- 两个辅助可留空，不能装两个同定义的辅助，即使实例 ID 不同。跨宿组合允许；历史所属不作硬性装备限制。
- 同一实例可被多个预设引用，只有激活预设计算一次；切换不复制实例，不重复叠加。
- 首版一把当前武器是实施预算；不恢复旧“四格背包/四武器槽”，不为多武器同时开火提前编写管理框架。
- 武器更换后，标签不适配的效果保留装配但标明失效原因、禁止触发；不能静默显示已生效。是否阻止装备可在 UI 阶段调整，统一规则即可。
- 先做数值装备，不要求人物外观随装备改变。LPC 穿脱与动作图层后置。

### 6.2 数据的唯一来源

- 新物品身份、分类、基础攻击值继续由 `data/items/items.json` 提供；扩展已有 `ItemCatalog`，校验重复 ID、字段类型、正值范围和引用。
- `effects.json` 当前的 `attack_style` 属于攻击行为配置，不等同于纯视觉特效。明确分开 `behavior_id`、参数与 `visual_id`，保留旧 `effect_id` 兼容映射。
- 新组件/词条可以放 `data/build/components.json`、`affixes.json`；物品表只引用 `component_definition_id`，不再抄一遍数值。
- 武器 `.tres` 可作为加载后的类型化配置或旧夹具；正式运行时同一数值只认一个来源，不让 JSON 与 `.tres` 各自编辑后猜优先级。
- 新增数据行只能复用已实现的行为类型。新机制需要代码处理器与测试，不能宣称“任意新攻击只改 JSON 就行”。
- 不可变定义、玩家库存实例、活动配置快照分开。继续以 `ProgressState` 持有永久数据；派生计算与运行触发用小组件/RefCounted，复用 `BuildRunService` 的入口或适配层，不增加第二套库存/存档 Autoload。

### 6.3 实例与派生值

- 材料按 definition_id 堆叠；核心/辅助按唯一 instance_id 存储，包含 definition_id、词条及数值、强化等级、收藏锁定。
- 星级属于定义身份，不在拾取时随机；星级不增加词条数，不改变固有效果。R4 先固定组件，R6b 才启用“两条不同的合法副词条”。
- 词条池不足两种时定义校验失败，不临时生成词条或默默减少条数。随机结果在掉落实例生成时确定一次，拾取、打开 UI、读档不重抽。
- 初版统一计算顺序：基础值 + 平值 → 同类百分比相加后乘入 → 显式条件倍率 → 上下限 → 最终整数伤害只舍入一次。攻速换算为间隔，设置最小间隔避免零冷却。
- 预览与战斗复用同一派生函数；详情区能列出基础值、每个来源及最终值。持续冷却、临时护盾、触发计数不保存为永久属性。

### 6.4 事件与触发安全

在现有 `Targeting.hit` 周围逐步扩展，不绕过统一伤害。建议最小上下文含：

`attack_instance_id`、来源实体、武器/Build 快照标识、目标、标签、基础伤害、破甲量、`origin_effect_id`、触发深度。

结算返回实际伤害、是否被无敌拒绝、是否产生破甲、是否击杀。事件分成攻击发出、有效命中、实际伤害、破甲开始、击杀，语义分别定义；攻击碰到无敌目标不能触发吸血或击杀奖励。

- 同一次攻击对同一目标去重；范围攻击命中多个目标时逐目标结算。
- 连锁/回响默认不再次触发同类派生效果；限制触发深度、每事件生成数、内部冷却，避免两个组件无限互相触发。
- 击杀事件只归属致死结算一次，奖励不要同时订阅多个死亡路径重复发放。
- Build 快照在攻击生成时冻结；切换后旧弹体沿用旧快照，不能一颗弹中途换两套加成。
- 状态按持有者清理：换场、重开、死亡不能残留事件订阅、计数和临时护盾；UI 关闭不影响战斗状态。

### 6.5 首批可观察的组合

机制名暂用测试名，不借未核验历史名冒充正式星官：

- **回响核心**：每 N 次基础有效命中，生成一次延迟小范围回响；回响不再触发回响。支持基础命中的各武器。
- **破阵核心**：基础攻击增加破甲贡献；只在破甲状态从无到有时触发一次局部冲击。没有护甲的敌人不虚构“破甲事件”。
- **猎获核心**：击杀给予有上限、有持续时间和内部冷却的护盾；不改玩家无敌时长，不无限叠加。
- 六个辅助建议：攻速、有效范围、投射物速度、破甲贡献、回响范围、护盾持续时间。初版各写清适配标签；前三个数值类先做，后三个按对应机制阶段补齐。

验收看“次数、范围、护盾、破甲与伤害来源”的区别，不只看三套都把 DPS 提高。单体木桩、密集弱敌、装甲目标分别用于测试；不要求每套在每种场景都最强，也不允许某套完全不能通关。

## 7. 保存、掉落和区域状态

- 延续进入村落的安全点保存；不要在这次路线里静默改成每次拾取立即写盘。
- 扩展同一存档快照：堆叠物、组件实例、Build 预设、当前装备、图鉴发现、唯一奖励标记、区域解锁；每次结构变更提升 schema 并实现旧档迁移。
- v1 数量字典原样保留；没有实例与 Build 的旧档使用空配置 + 基础武器，不凭旧样例模块虚构玩家已拥有的核心。教学礼包如需提供，必须一次性领取并与领取标记一同保存。
- 同一内容从堆叠改实例时明确数量转换策略，迁移只做一次；未知定义保存为不可装备的隔离条目或保留原始数据，不能升级即永久删除随机战利品。
- 存档版本过新拒写，主/备损坏恢复、临时文件提交、跨进程验证继续有效；迁移失败保留原文件。
- 唯一宝箱/Boss 首次奖励：奖励实例与 `reward_claim_id` 在同一内存事务更新，并同一安全点快照保存。崩溃重启允许回滚整段未保存探索，不能保留物品却丢领取标记。
- 普通敌人掉落可重复，使用每次遭遇唯一死亡/掉落实例 ID 防同帧重发；不同遭遇不是同一个一次性对象。
- 地上未拾取物首版不跨场景保存，离场提示规则；回村/重进是否重刷敌人按区域策略配置。默认建议普通遭遇重刷，唯一资源不重置，Boss 可重打但首次奖励不重发。
- 死亡建议回最近安全入口、不新增资源扣除；失败退出也会进入村落保存当前内存进度，应明确其影响。此项与 Boss 重试策略在 R9b 前确认；不能自行删除已获得物品。
- 货币、买卖、拆解返还与制作材料均通过一次校验/扣除/发放事务；首版先材料制作，货币未定时商店仍只显示目录。

### R2：物品表、实际武器和装备 UI 打通

- 范围：`ItemCatalog`、`WeaponEffectLink`、物品/效果 JSON、类型化武器配置、`ProgressState/Store`、独立装备页或背包行。引入最小自动武器运行节点，不扩成通用行为脚本语言。

### R3：可供 Build 使用的结算与事件

- 范围：`combat_targeting.gd`、敌人/装甲接口、弹体与自动区域攻击、`run_stats.gd`。增加小型上下文/结果结构和明确事件，旧 `hit()` 可作兼容包装。

- 验收：无敌无伤害无吸血；致死事件唯一；范围命中多目标各一次；墙优先于墙后敌人；一次攻击使用固定来源快照；测试触发递归受限。

### R6a：数据化掉落表

- 闭环：不同敌人/宝箱按各自表掉武器、材料或固定组件；拾取进入正确库存。
- 范围：建议 `data/loot/loot_tables.json`、小型生成器，复用已有死亡信号和掉落场景；野狼与普通野兽分别接入。

- 验收：固定随机种子可复现；非法权重/引用可诊断；同次死亡只发一次；普通敌人重刷可再掉；唯一奖励不重发；背包已满等未来规则不提前引入。

### R6b：随机组件实例与比较

- 闭环：获得两件同名组件、两条合法随机副词条不同 → 比较 → 收藏/锁定 → 选择一件装配 → 重启后值不变。
- 范围：词条池与实例生成、比较详情、筛选/锁定、序列化；基于 R4 已有实例，不重造库存。

- 不做：重铸、升星、未知词条随机拼装。下一步 R7a，或按依赖进入 R8a。

### R7a：自动重锤

- 闭环：装备重锤 → 自动慢速范围冲击 → 装甲敌人更快破甲 → Build 同样生效。
- 范围：新增一个武器数据条目和必要行为处理器，复用圆形区域、伤害和破甲；UI 显示间隔、范围、破甲量。
- 验收：不依赖蓄力按钮/动画；单次多目标各结算一次；有等待代价、不锁玩家动作；装甲与无甲目标差异合理，剑并非无法破甲。

### R7b：自动弓

- 闭环：装备弓 → 选敌发射箭 → 飞行命中/被墙挡 → 投射物相关辅助产生可见变化。

- 验收：发射前无伤害；目标运动可躲过非制导箭；薄目标不漏判；先墙先停；默认首个目标即止；暂停/重开不残留弹体。
- 下一步 R7c。

### R7c：自动单发火铳与少量变体

- 闭环：自动开火 → 装填计时 → 再次开火；与弓形成慢爆发/高破甲差异。
- 范围：自动装填行为、高速弹体和 HUD 装填条；先不加弹药库存。再单独补一把剑或弓的行为变体，优先有限穿透或多发，不能同时堆多种新机制。
- 验收：换装备、暂停、死亡不能绕过装填；高速薄墙/近目标正确；多发/穿透逐次去重、明确最大数量和伤害衰减；额外子弹不无限触发 Build。
- 达到 4 类武器后先比较，不立即扩展长枪、连弩和脉冲枪。下一步完成 R8。

### R8a：普通敌人与装甲敌人复用

- 闭环：外围遭遇普通野兽/野狼，深处试验组合有装甲单位；击败后各有掉落。
- 范围：将现有野狼巡逻/察觉/追击/恢复和装甲接口用于有限新敌人；行为配置、生命、掉落来源保持清晰，避免万能巨型 AI。
- 验收：绕障不穿墙、不因地形永久卡在出生点；活动范围有效；攻击有预警/恢复；死后不攻击不重复掉落；同一武器对不同敌人呈现策略差异。
- 先用有意义的小布局解决阻挡，确有卡死证据再加最小导航。下一步 R8b。

### R8b：远程敌人与精英扑击者

- 分两次任务：先远程机械单位，再老虎或狼王之一；普通敌人不能仅换色涨血冒充精英。
- 远程：保持距离/驻守、可见弹道、射击预警与冷却；复用通用目标过滤，敌弹不能伤自己或误计玩家 Build。
- 精英：锁定方向扑击或有节奏连续追击，提供落空恢复；用几何轮廓/冲刺轨迹表现即可。
- 验收：混合遭遇仍有安全空间；不隔墙射击/扑击；自动选敌不因不可达目标永久停火；至少两套 Build 能完成遭遇。
- 下一步 R9a。

### R9a：森林深处与区域奖励身份

- 闭环：村落 → 外围 → 深处支路 → 获得该区组件/素材 → 按入口返回。
- 范围：新增深处场景，复用 `SceneFlow`、`scene_exit.gd`、出生 Marker、边界与 UI；优先可编辑地面和独立障碍。
- 区域配置包含区域 ID、敌群、掉落表、唯一交互 ID、出口和建议威胁说明。无程序化大地图。
- 验收：10 次往返无重复玩家/入口回传/墙内出生；两区至少两种遭遇组合；区域威胁不全局随玩家等级涨；持有、Build 快照与一次性资源状态正确。

## 9. 功能占位美术计划

### 9.1 新验收门槛

以“认得出、看得清、能替换”为准。允许当前猎人图、借用像素素材和程序化几何共存，但同屏像素尺度、方向、脚底锚点、碰撞占地与 UI 层级必须可读。无需等待 A0 定稿，也不继续投入玩家攻击图集。

优先顺序：已有可用资源 → 授权明确的现成素材 → 简单几何/文字 → 确有缺口时的小量生成。imagegen 是可选工具，不是默认每批必用。当前不安装新美术流水线或付费服务。

### 9.2 按玩法交付的小包（V 系列）

- V0 / R1–R2：角色待机/走路、敌我轮廓、生命条、剑弧/箭矢/命中点；缺图可几何兜底。
- V1 / R4–R6：3 核心与 6 辅助的可辨图标、触发提示、材料/武器类别图标；可先颜色 + 不同形状 + 简称。
- V2 / R7–R8：锤圆、弓箭、火铳闪光/装填、装甲标志、扑击箭头、远程敌弹；预警必须高于地面装饰优先级。
- V3 / R9：林地/设施地面、墙、树、岩石、门与出口标记；一套素材包先覆盖一个区域，避免每阶段重新换全项目风格。
- V4 / R11：一套轻量 UI 主题与统一占位图标；不要求手绘整页背景。

旧 A0–A9 保存为长期候选；原始样板、LPC、猎人图不覆盖、不删除。`动画资源整合/` 是用户未跟踪目录，本次未扫描；未来仅在对应素材任务中确认内容和授权。

### 9.3 借用资源交付契约

每个进入运行场景的素材记录 asset_id、源地址/作者/上游版本、许可及署名要求、原始文件、处理后文件、用途、尺寸、帧序与锚点、运行引用、替换条件。许可不明确则不用它做发行占位；“网上可下载”不等于可分发。

复用本地 Ninja Adventure/LPC 时核对项目现有 CREDITS 和具体条目，不能假设整个目录同一许可。复制资产不等于导入第三方代码插件。

地图地面、阻挡物、前景分开；树干决定碰撞、树冠决定遮挡；不把背景上的房屋/树当可交互物。图集尺寸由素材决定并用 profile/offset 适配，不把旧 64×64 作为所有素材统一规格。

占位更换使用新版本文件名与显式引用，不无声覆盖正式资产；Gameplay ID 与图片路径分离。替换不得改变伤害、掉落或存档语义。
