## 本次完成（S4 一个手动攻击与闪避控制原型，2026-10-18）

阶段：新总路线 S4。用户本轮确认：
- **D1**：鼠标指向瞄准，攻击朝鼠标方向，鼠标左键攻击，空格闪避；

没有做完整四武器、技能栏、最终动作数值、动作图集或联机同步。

### 已完成内容
- **玩家动作组件** `ActionController`（`scripts/combat/player_action_controller.gd`，挂在 `player.tscn` 下）。状态有：待机、前摇、生效、后摇、闪避、受击硬直、死亡。
  - **攻击**：左键按下时锁定瞄准方向。前摇 0.12 秒 → 生效 0.08 秒（扇形 110°、半径 76，每帧检查，同一攻击实例对同一目标只伤害一次，并检查墙体遮挡）→ 后摇 0.22 秒。攻击期间移动速度降为 35%。伤害沿用当前木棍定义（含模块加成）。
  - **闪避**：0.24 秒、速度 560，前 0.2 秒无敌，结束后 0.15 秒才能再闪避。不消耗耐力。有移动输入时朝移动方向闪避，否则朝瞄准方向。
  - **取消规则**：前摇和生效不可取消；后摇可被闪避取消。攻击只能从待机发起。
  - **输入缓冲**：只有一格，保留最近一次按键 0.2 秒；暂停时清空；受击时清空。
  - **受击与死亡**：受击打断当前动作并硬直 0.18 秒，之后恢复控制；死亡后不再响应。
  - **画面**：瞄准短线、攻击扇形（前摇淡黄、生效橙、后摇灰）、闪避无敌时半透明；攻击期间角色朝瞄准方向。都是调试画面，等 A2 动作图集。
  - 以上数值全部是导出的测试值，不是最终手感。
- **`player.gd`**：移动速度由动作组件决定；闪避无敌期间不受伤；受击通知动作组件。`layered_character.gd` 新增 `set_facing`，用于攻击时朝向。
- **自动攻击开关**：`SettingsStore` 新增 `auto_attack`（默认 false），写入 `settings.json`，schema 不变，缺字段时取默认值。
  - 直接运行场景时会先读盘再保存，不会用默认值覆盖已有的音量和窗口设置。
  - 按 T（动作 `auto_attack_toggle`）切换；开启时玩家头顶显示「自动攻击」。
  - 自动木棍和弹弓只在开启时自动索敌；已开始的挥击会照常完成。
- **InputMap**：新增 `attack`（鼠标左键）、`dodge`（空格）、`auto_attack_toggle`（T）。点击 UI 按钮不会触发攻击，因为攻击走的是 `_unhandled_input`。
- **动作试验场** `scenes/exploration/action_training.tscn`：可直接运行，不接入主流程。四周有墙，一个 30 血训练木桩（不移动、无接触伤害），一个红圈预警测试攻击（空闲 1.2 秒 → 预警 0.7 秒 → 半径 64 内结算 1 点伤害，脚本 `scripts/combat/training_hazard.gd`），并接入暂停菜单。
- **提示文字**：外围提示和竞技场 HUD 加上了「左键攻击 · 空格闪避 · T 自动攻击」。

### 当前联机同步模型

- 当前代码采用房主/服务器权威的输入与状态同步，不是帧同步或确定性锁步；服务器负责移动、敌人、自动攻击、伤害和胜负。
- 客户端每个 `_physics_process` 通过可靠 RPC 提交移动方向；服务器每个物理帧向客户端发送玩家/敌人位置，位置 RPC 使用 `unreliable`，客户端收到后直接设置坐标。石弹位置也按物理帧频率发送。
- 生命、波次、生成/移除等离散状态使用可靠 RPC。当前没有帧编号/状态序号、客户端预测、远端位置插值或回滚。
- 这足以作为本机双开原型，不代表已验证局域网或高延迟表现。客户端移动需经服务器往返且没有本地预测，可能感到输入延迟；连续输入可靠逐帧发送可能在网络拥塞时积压；无序位置包和直接设置坐标可能造成回退或抖动。Godot 文档也区分了可靠有序传输与可能丢失、乱序的 unreliable 传输，并提示 reliable 有性能成本。
- 阶段 3.1 和本轮 3.2 均未改网络实现或引入帧同步。恢复 2.2 时观测真实设备表现，再单独确定状态采样频率、序号/有序传输、插值或预测需求；具体以实测为准。
- 参考：[Godot 4.7 高层多人游戏 API](https://docs.godotengine.org/en/4.7/tutorials/networking/high_level_multiplayer.html)。
