# TribeHunt 项目方案

更新：2026-10-20 · 当前方向：自动战斗、Build 与内容扩展优先。

## 项目定位与循环

文明重启背景的俯视角探索与构筑游戏。玩家通过武器、星宿核心和星官辅助形成战斗策略，在自然荒野、废弃设施与遗迹中走位探索，依靠自动攻击对抗不同敌人，收集战利品并回到基地整理、制作和保存。

主要乐趣是“组合有什么效果、下一件掉落能怎样改变玩法”，而不是手动连招或逐武器攻击动画。当前优先单人，合作与联网后置。

循环：准备武器与 Build → 探索/走位/自动战斗 → 获取武器、组件、材料与图纸 → 比较装配与机制展示 → 回村保存 → 挑战不同区域。

## 最新决定与边界

- 玩家攻击自动化；不再以鼠标瞄准、连击、蓄力输入及玩家攻击动作美术作为开发主线。
- 保留移动、闪避、受击、碰撞、伤害、破甲、独立投射物、敌人预警与恢复等可复用能力。
- Build 的建立和可视化、武器差异、敌人/地图/掉落内容、UI 与基础美术占位优先。
- 美术服务功能：允许风格调整、授权现成资源和几何占位；不要求 A0 定稿或完整 LPC 攻击换装。
- 正式场景、库存、构筑 UI 必须来自同一数据来源；自动战斗的效果必须可测量和可解释。
- 联机、云服务、Steam、Workshop、完整星宿内容、复杂元素反应与最终美术仍后置。

## 当前代码与目标的区别

当前已存在：正式自动攻击 `EquippedAutoWeapon`、角色级一核心两辅助、四类试验武器、五场景连通、掉落/制作/拆解/强化、测试区间成长、背包/图鉴/HUD/结算、安全点存档 schema 4。旧手动剑与木棍/弹弓仍作回归夹具，默认不作为玩家输出。

尚未完成：导出包、20 分钟稳定性窗口、人工两轮五场景、正式美术统一、联网。没有弹药库存、长枪或自由加点。

## 首版方案建议

首版建议一把当前武器、一套角色级 Build（一个核心、两个不同辅助），跨宿可组合；多个预设仅激活一个。定义与实例分开，固定核心机制与星级，随机副词条后续加入。该结构在 R4a 前确认，不能与旧“每把武器一宿两官+本宿共鸣”叠加实现。

建议切片预算：3 核心、6 辅助、4 类武器、至少 6 种敌人定位、5 个连通场景。先完成两套 Build 的真实获得/装配/自动触发/展示/保存闭环，再增加内容；数量不是最终上限。
