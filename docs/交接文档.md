## 3. 打开与运行
1. 安装 / 使用 Godot 4.7.2
2. 导入并打开 `tribe-hunt/project.godot`
3. 主场景：`res://scenes/menu/main_menu.tscn`
4. F5 进入主菜单
5. 单人可玩路径：开始远征 → 单人 → 出征准备里选择撤离节奏对照 → 确认出征 → 竞技场（WASD / 方向键移动；Escape 暂停）。前两波按所选节奏撤离或继续并调整构筑；第三波清场后进入野猪王，击败后狩猎成功。
6. 本机联机：主菜单 → 在线合作 → 创建/加入 →「进入移动测试」。服务器自动用临时木棍/弹弓结算，两端应看到相同的敌人 HP、波次和胜负
7. 设置：主音量、窗口/全屏；文件位于 Godot `user://settings.json`（本机常见路径：`%APPDATA%/Godot/app_userdata/TribeHunt/settings.json`）

直接打开竞技场场景仍可调试战斗，但正式流程应从主菜单进入。

### 临时构筑预览（3.1，不是正式入口）
在 Godot 里直接运行 `res://scenes/build/build_preview.tscn`。主菜单没有进入该场景的按钮。它只显示样例定义，并用按钮核对「已发现独特星点」和「当前装备件数」。这些按钮不代表掉落、槽位或重复装备规则已经确定，也不写存档。

### 单人构筑原型（3.2）
正式体验路径：主菜单 → 开始远征 → 单人 → 出征准备。出征前可勾选木棍/近战适配模块（攻击速度 +20%）和弹弓/远程适配模块（攻击范围 +20%）；波间每个非最终波次清场后暂停，可增减样例模块再继续。HUD 显示当前生效构筑。

这里的模块是供原型直接选择的样例，不经过玩家收藏、掉落、解锁或存档；效果数值只用于感受构筑差异。槽位上限、武器切换、星座效果、元素与成长规则均未定。该系统只接入单人竞技场，不同步到联机测试场。

### 本机双开
- **2.1.1 会话 UI 复验已通过（用户确认）**；**2.1.2–2.1.4 已自动化验证**。建议再目视看一局双窗口战斗。
- 回归步骤：A 创建房间 → B 加入 `127.0.0.1:7777` → 进入移动测试 → 确认两端敌人被服务器击杀、HP 与波次一致，最后都显示「狩猎成功」。离开后对端角色消失。
- 可选命令行：`-- --session-host --session-move-test` / `-- --session-join --session-move-test --session-probe`。
- 本机地址只用于同一台电脑上的两个进程。它不能代替 2.2 的第二台设备。

### 2.2 局域网人工步骤（冻结；恢复联调时执行）
检查时间：2026-10-16。Godot `4.7.2.stable.official`。这台电脑是 Windows `10.0.26200`，WLAN `192.168.3.8/24`，网络类别 Public。房主无头探测时 UDP 监听为 `0.0.0.0:7777`，进程已停止。同网卡只看到网关 `192.168.3.1`。没有 UDP 7777 入站规则。

两台设备都运行同一份 Godot 4.7.2 工程或同一导出包。客户端地址填房主当时的 WLAN IPv4，不要填 `127.0.0.1`、`169.254.*` 或名为 Meta 的虚拟网卡。端口保持 `7777`。开打前在房主电脑上重新看一次 WLAN 地址，DHCP 可能变化。

房主若收不到加入，先由用户自己放行**一个**入站端口，不要关闭整个防火墙，也不要开放其他端口。当前这块 WLAN 被标成公用网络，所以规则必须作用在「公用」配置文件上；只勾专用网络不会命中。

1. Win + R，输入 `wf.msc`，打开「高级安全 Windows Defender 防火墙」。
2. 入站规则 → 新建规则 → 端口 → UDP → 特定本地端口 `7777` → 允许连接。
3. 配置文件只勾选「公用」。名称可用 `TribeHunt LAN UDP 7777`。
4. 测完后可禁用或删除这一条规则。

等价的一条命令（仅在房主上、由用户自己执行）：

```powershell
New-NetFirewallRule -DisplayName "TribeHunt LAN UDP 7777" -Direction Inbound -Protocol UDP -LocalPort 7777 -Action Allow -Profile Public
```

对局步骤：

1. 房主：主菜单 → 在线合作 → 创建测试房间。状态应显示监听端口 7777。
2. 客户端：把地址改成房主 WLAN IPv4，端口 7777，点加入。成功时应显示连接成功，两端人数为 2。超时则核对同一局域网、地址和上面的单端口规则。
3. 任一端点「进入移动测试」。核对：两人身份不同（「你」与「同伴」）；各自 WASD 只移动自己；敌人由房主生成并追逐；敌人生命、波次和最后的「狩猎成功」两端一致。
4. 客户端离开会话。房主人数回到 1，客户端角色消失。
5. 重新创建并加入，再确认一次进入测试场、至少一波击杀，以及离开后的清理。
6. 两端回主菜单。任一台走：开始远征 → 单人 → 确认出征。本机已在 2026-10-16 跑通该路径至「狩猎成功」并返回主菜单。

### 碰撞层约定
- 1：玩家。玩家 `collision_mask` 为 8，只阻挡野猪王身体，不阻挡普通敌人
- 2：敌人。野猪王同时在这一层，石弹才能命中
- 4：石弹（mask=2，只打敌人）
- 8：野猪王身体碰撞。视觉身体比这个圆更大，并向上偏移

### 关键导出参数
- `Player.move_speed`：默认 220；`max_hp` 默认 8；`hurt_invuln_seconds` 默认 0.6
- `MeleeWeapon.damage`：默认 1；`attack_range` 默认 72；`cooldown` 默认 0.45
- `RangedWeapon.damage`：默认 1；`attack_range` 默认 320；`cooldown` 默认 0.85
- `StoneProjectile.speed`：默认 420；`lifetime` 默认 2
- `Enemy.move_speed`：默认 120；`contact_damage` 默认 1；`max_hp` 默认 3
- `WaveConfig.enemy_count` / `spawn_interval`：见 `data/waves/*.tres`
- 场地半尺寸默认 `(480, 270)`，相关节点请保持一致

### 输入动作
- `move_left` / `move_right` / `move_up` / `move_down`（WASD + 方向键）
- `pause`（Escape）：单人战斗暂停
- 菜单返回另使用引擎默认 `ui_cancel`

### 分组
- 玩家：`player`
- 敌人：`enemies`。野猪王也在这组，所以现有木棍和石弹能打到它
- 野猪王：`boar_king`
- 单人运行统计：`run_stats`

## 6. 资源替换约定
1. 美术只放 `assets/`，数值只放 `data/` 或脚本导出变量。
2. 替换贴图时保持路径与文件名不变，例如始终使用 `res://assets/sprites/player/player.png`。
3. 新增敌人/武器贴图时，先在对应子目录放占位图，再在场景里引用。
4. 不要在脚本里用绘制色块代替最终角色表现；占位也尽量走 `Sprite2D` + `assets/`。
5. 野猪王当前仍引用 `assets/sprites/enemies/enemy.png`。以后单独做野猪王图时，只改 `BoarKing/BodySprite`，不要改普通敌人那张图。尺寸、偏移和界面节点见 `docs/UI与精灵美术交接清单.md`。

### 联机同步模型审查（代码现状）
- 当前是服务器权威输入/状态同步，不是帧同步或确定性锁步；服务端裁定移动、敌人、伤害和胜负。
- 客户端每个物理帧通过 reliable RPC 发送移动向量；服务器每个物理帧发送玩家/敌人位置，使用 `unreliable`，客户端直接设置位置。石弹位置也逐帧同步；生命、波次、生成和移除使用 reliable RPC。
- 未实现帧号/快照序号、客户端预测、远端插值或回滚。客户端移动需服务器往返，跨网可能感觉输入延迟；逐帧 reliable 输入可能因网络拥塞积压；unreliable 位置可丢失或乱序，直接设置位置可能抖动或回退。当前本机双开不能验证多设备网络表现。
- 阶段 3.1–3.2 均未改网络代码或实现帧同步。2.2 恢复后根据设备实测评估快照频率、序号/有序传输、插值或预测；参考 [Godot 4.7 高层多人游戏 API](https://docs.godotengine.org/en/4.7/tutorials/networking/high_level_multiplayer.html)。
